# Translating Atlas: procedure

English is the source. pt-BR is a required language: a PR that adds or changes English text ships the pt-BR in the same PR, and `bun run i18n:check` (inside `bun run check`) fails otherwise. This file is THE procedure. Layout and why it is built this way: `i18n/README.md`. Style: `i18n/style/`. Terms: `i18n/glossary.yaml`.

## One source tree

Every message of every surface lives once, in `i18n/messages/<area>/`: `en.json`, `pt-BR.json`, `meta.json` (English-only descriptions and flags), `lock.json` (written by the tools). An area is a small folder by topic (`settings`, `nav`, `config`); **every key of an area starts with `<area>_`**, so the key tells you the folder and the folder tells you the keys. Shared words (Cancel, Delete, Trash, key names) are defined once in `common`, `common_os`, `common_keys` and every surface gets them. The `area.json` of each area (`{ "surface": "desktop" }`, never listed in a shared file) says which surface consumes it; `i18n/surfaces.json` holds only per-surface config. Nothing generated is committed: Paraglide's input is built into the gitignored `.i18n/` of each app, Rust reads the same JSON at build time.

## The loop

1. **Find before you add.** `bun run i18n:find "Cancel"` (a text) or `bun run i18n:find settings_display_language` (a key: its file:line, values and usages). If the text exists, use its key. Shared words are `common_*`: `m.common_action_cancel()`, `t!("common_action_cancel")`.
2. **Add.** `bun run i18n:add settings_host_name "Terminal host" --desc "Name of the tile in Settings > General" [--pt-BR "Host de terminais"] [--surface desktop] [--new-area]`. It picks the area from the key (the longest area name it starts with), refuses a duplicate of a common text, writes en/meta/pt-BR sorted and stamps the lock. A new area needs `--new-area --surface <s>` (it writes the area's `area.json`). A branch from before the registry change: `git merge origin/main`, `bun run i18n:migrate-registry`, `git add -A i18n`, commit. Without `--pt-BR`, run `bun run i18n:translate --locale pt-BR --area <area>` (your own `ANTHROPIC_API_KEY`, or `I18N_BASE_URL` for any OpenAI-compatible endpoint such as Ollama; it validates before it writes) or write it yourself; a native speaker still reads the PR (CODEOWNERS routes it).
3. **Use it.** Desktop and site: `m.settings_host_name()`. Rust: `t!("settings_host_name")`. Never a literal.
4. **Check.** `bun run i18n:check`. Every finding is `file:line rule key message` and names the command that fixes it; `--json` for tools, `--surface <name>` for one surface, `--status` for freshness per area. `bun run i18n:fix` sorts files and rewrites locks (**never hand-write a lock**); a typo-only English edit that must not invalidate the translation: `bun run i18n:fix --restamp <key>`.

An English edit that changes the meaning makes the pt-BR **outdated** (the lock holds the hash of the English the translation was made from); retranslate, then `i18n:fix`.

**Rename or move:** `bun run i18n:mv old_key new_key` moves values, meta and lock stamps across areas and rewrites `{@old}` and every call site it can prove: through whatever name a file binds the messages to (desktop `#lib/i18n/m.ts`, Paraglide's `messages.js`, `* as ns`, `{ m as msg }`) `m.old(`, `m?.old(`, `m["old"]`, `const { old: x } = m`, `import { old as x }`, and in Rust `t!("old"`, `t_in!(tag, "old"`, `lookup`/`lookup_on`/`translate(tag, "old"`. Anything left that could still reach the old key makes it **exit 1 listing `file:line why`** (the catalogs and the provable sites are already moved; edit the rest by hand, then `i18n:check`): a mention that is no call (a string, a comment), a key built at run time (`m[\`old_${x}\`]`, `m["old_" + x]`, a Rust `format!("old_{…}")` next to a `lookup`, an `// i18n-keys: old_*` glob that covers it), a shorthand `const { old } = m` or `import { old }` (needs a local rename), a rest destructure. **Fold a duplicate:** `bun run i18n:mv <dup> <existing> --into` (the fix for `dup-value`) deletes `dup` in every locale, meta and lock and rewrites its call sites and `{@dup}` references to `existing`; it refuses another English, an unknown target, a target area a surface using `dup` does not consume (move the target to a `common_*` key first: rename one of the two with plain `i18n:mv`, then fold the rest), and **any locale where `dup` is translated differently from `existing`** (same English is not the same message: a state is not a verb, "All" has a gender; it lists the locales and both values and writes nothing). Decide per pair: same role and same text everywhere, fold; same role and `dup`'s pt-BR is the better one, `--take pt-BR=dup` (replaces the target's text in that locale, one locale per `--take`, never the English); same role and the target's is better, give `dup` that text and fold; different role, keep both and write `i18n-distinct: <the two roles>` in the description. **Delete a key:** remove it from `en.json`, `meta.json` and every locale file of its area, then `i18n:fix`. **Add a language:** `bun run i18n:add-locale <tag> --owner @user`; it creates `<area>/<tag>.json` in every area and edits `locales.json`, `SUPPORTED`, `Info.plist`, the project settings and CODEOWNERS, and `supported-sync` keeps those lists equal. All of these take `--json` for agents and exit 1 with the fix command in the error.

## Moving existing hardcoded text (the migration)

Text that is already in a component is moved by `bun run i18n:extract <path-or-glob> [--area <area>] [--dry-run] [--json]`, not typed message by message. It handles `.svelte` files (desktop and site islands): text nodes and the static `title`, `placeholder`, `aria-label`, `aria-description`, `alt`, `label`, `tooltip`, `description`, `message` attributes (kit components included). It writes the English and a derived description (`meta.json`), reuses a `common*` key when the English is the same (never a duplicate), replaces the text with `m.<area>_<component>_<words>()` (importing `m` from `#lib/i18n/m.ts`, or from Paraglide on the site), and calls `i18n:fix`. It does **not** write pt-BR: run `bun run i18n:translate --locale pt-BR --area <area>` (default; same prompt, glossary and validation for every batch), or write it yourself when no key is configured, then `i18n:fix` and `i18n:check`. Run it with `--dry-run --json` first.

It leaves what it cannot convert safely and lists it in the report (`file:line`, `reason`): `plural`, `concatenation` (text joined to a call or computation), `inline-markup` (a sentence split by `<b>`/`<a>`), `expression-literal` / `template-literal` (a string inside `{...}`), `shortcut` (use `kbd()`), `near-common`, `catalog-rule`, `shadowed-m` (rename your local `m`, run again), `identifier-like`, `url`, `braces`, `ambiguous-variable`, and every string in `.ts` modules and `<script>` blocks (`ts-module`, `script-string`, a heuristic list). Migrate those by hand with the procedure above. Never convert code identifiers, CSS, test ids, URLs, `<code>`/`<kbd>`, or machine output.

Rust is never rewritten by a tool: `bun run i18n:extract crates/atlas-cli/src/commands/link.rs --json` prints a worklist per site with a kind (`text`, `vars`: the suggested English and the exact `t!` call; `judgement`: ANSI colors, `{:>8}`/`{:?}` specs, multi-line; `machine`/`log`: add `// i18n-ignore: <reason>`; `uncounted`). Apply it by hand; machine output (`machine_output.rs`) and logs stay English. The batches, their order, the quality loop (an independent AI pass fixes the pt-BR; layout pass in pt-BR for overflow) and how tests that assert English are handled (they run in `en`; never assert pt-BR outside the catalog tests) are in `i18n/MIGRATION.md`.

## Message syntax (one subset everywhere)

A value is a string, or one variants object. `{name}` is a variable. `{@common_os_trash}` references another message and is inlined: "Moved to {@common_os_trash}" becomes an `os` select by itself. Plurals and `os` use `declarations` / `selectors` / `match`:

```json
"files_count": [{ "declarations": ["input count", "local countPlural = count: plural"], "selectors": ["countPlural"],
  "match": { "countPlural=one": "{count} file", "countPlural=*": "{count} files" } }]
```

An exact zero is a second selector (`"local countExact = count"`, match `countExact=0, countPlural=*`). `os` is `"input os"`, selector `os`, match `os=mac`, `os=windows`, `os=*`. Markup is `{#link}..{/link}` (Paraglide only). The Rust evaluator and the Paraglide compiler read exactly this; `i18n:check` rejects anything else.

A sentence with an emphasized or linked span is ONE message with markup tags, never pieces around an element. On the desktop it renders with `lib/i18n/Rich.svelte`: `<Rich parts={m.key.parts({ n })} tags={{ em: "em", b: boldSnippet }} />` (a tag is an element name or a snippet that receives the tag's content; define the snippet in the component that owns the scoped CSS). `m.key()` on the same message returns the text with the tags dropped.

## Where the code calls it

| Surface | Call site | Notes |
|---|---|---|
| Desktop (`apps/desktop`) | `m.area_name()` (`import { m } from "#lib/i18n/m.ts"`) | Call `m.*()` inside templates, `$derived` or functions, never at module top level or cached in a plain variable: the locale is Svelte `$state` and switches live. Always a static `m.key`: messages tree-shake into the chunk of the screen that uses them (the startup bundle does not grow with the catalog), and `m[variable]`, `Object.keys(m)` or passing `m` around would pull every message into it. Dates, numbers, relative time: `$lib/i18n/fmt`, never a hand-made `ago()` or `n === 1 ? "" : "s"`. `bun run i18n:compile` (and vite) generate `.i18n/` first. |
| Site (`site`) | `m.*()` in `.astro`/`.svelte` | Chrome strings and docs banners. Pages that do not exist in pt-BR get no hreflang. |
| Rust: CLI, TUI, hostd, desktop shell | `atlas_i18n::t!("area_name", name = value)` | `os` is added by the i18n layer: call sites never pass it. `t_in!(tag, "key")` renders in an explicit language (the native menu models are built from a tag so a test compares `en` and `pt-BR`). The desktop shell is long-lived: Settings → Language calls `atlas_i18n::set_lang` and re-labels the native menus in place (`menu::language_changed`); the CLI reads the language once. |
| clap `--help` | the English doc comment stays the source | The English of `cli_*` areas is generated: add a command's path to `MIGRATED` in `crates/atlas-cli/src/cli_i18n.rs`, run `UPDATE_FIXTURES=1 cargo test -p atlas-cli cli_i18n`, then write the pt-BR lines. Subcommand names, flags and env vars are API and never translate. |
| Docs | `docs/pt-BR/<slug>.md` | Front matter `title`, `source`, `source_sha` (the git blob sha of the English file at translation time, `git hash-object docs/<slug>.md`, a quoted string). An AI-translated page also carries `translation: machine` (the site shows a "tradução automática" banner) until a person reviews it; the reviewer removes the line. **A PR that edits or adds an English page in `docs/` ships its pt-BR twin in the same PR**: update the translation for what changed (`git diff` of the English since the old `source_sha`; only those parts) and set `source_sha` to the new blob sha, else `docs-outdated` (or `docs-missing` for a new page) is an error in PR and diff mode (a snapshot only warns, and so does a page the change does not touch). The escape, when the translation cannot ship now: in the twin's front matter `translation: pending` plus `issue: https://github.com/<owner>/<repo>/issues/<n>`; the site keeps the outdated notice, and you remove both lines when it lands. Cite UI names in the translation exactly as the pt-BR catalog spells them (Settings paths, tabs, buttons, TUI headings). Code blocks stay byte-identical except comments. `CHANGELOG.md` is never translated. |
| Mobile (`apps/mobile`) | gen_l10n | A surface with `"arb": "<dir>"` in surfaces.json (its areas say `"surface": "mobile"` in their `area.json`): `i18n:generate` writes the `.arb` files (ICU plural/select, descriptions) at build time. |

## What i18n:check enforces beyond the catalogs

`unused` (a key none of its consuming surfaces references; `common*`, generated and `cli_*` areas exempt; dynamic use: `// i18n-keys: prefix_*`), `undefined-key` / `unconsumed-key` (a `m.x(` or `t!("x")` whose key is not in the tree, or is in an area that surface does not consume), `dup-key` (one key in two areas), `dup-common` (an English text equal to a common one: use it, or say why in meta `distinct`), `dup-value` (the same English under two keys: a warning only when a locale translates them differently, info when consistent; never fold keys of different screens just because the English matches), `common-sentence` (common areas hold terms, not sentences), `budget` (an area file over 150 keys or 24 KB: split it by key prefix), `dangling-ref`, `area-surface` (an area with no, an unknown or a malformed `area.json`), `supported-sync`, plus the writing lint and the ratchets below.

`frozen` (desktop and site, an error, no baseline): a message function called once keeps the language of that moment, and the desktop switches live. The check reads the AST and flags a `m.*()` call evaluated at the top level of a `.ts` / `.svelte.ts` file or a `<script module>` block (also inside an object, array or `$state(...)` built there), in a class field or static block, in the instance script of a `+layout.svelte`, and in a command registered with the keymap's `register([...])` or built by a function that returns `Command[]`. Inside a function, a getter, `$derived`, `$effect` or the template it is fine. Fix with a getter (`get label() { return m.x(); }`), a thunk (`label: () => m.x()`, `named([...])` for commands once #600 lands) or `$derived`; a genuine case (English-only machine text) says why on its line or the line above: `// i18n-allow frozen: <why>`. A message reached through another function (`const ITEMS = build()`) is not followed: keep such builders out of module scope.

## Never translate

`--json`, MCP tools and descriptions, `skills/`, logs, exit codes, the hostd protocol (stable `code` plus `args`; the English `message` is for logs and old clients), install scripts, `llms.txt`, `CHANGELOG.md`, push relay payloads (only event kind, pane key and `<agent> · <folder>` ever leave the machine). Human output (`println!` for a person, the `error:` / `warning:` / `caused by:` prefixes of `crates/atlas-cli/src/chrome.rs`, clap's `error:` and `tip:`, `▸` lines) is translated; **a program never parses it** (the `hint:` and `error:` lines `crew install` prints for the desktop to read stay English).

**The machine channel.** A command that something else drives takes `--progress json` and prints NDJSON on stdout, one event per line: `{"v":1,"kind":"step"|"info"|"hint"|"error","code":"<stable dotted id>","args":{...},"message":"<English>"}` (contract and `Coded` error type: `crates/atlas-core/src/progress.rs`; `atlas crew install --progress json` is the first user). A consumer branches on `kind` and `code`, never on text; a new failure a client must tell apart gets a `code` where the error is created (`progress::Coded::new("sudo.password_rejected", args, english_message)`). Atlas Desktop must read only this channel; the old `step:` lines stay for old clients until the migration of `installProgress.ts`. `crates/atlas-cli/tests/machine_output.rs` runs the machine commands under `ATLAS_LANG=en` and `ATLAS_LANG=pt-BR` and compares the bytes, and `tests/crew_install.rs` does it for the install events: add a row for every new machine surface.

## Platform words (OS-aware text)

Atlas runs on macOS, Windows and Linux; no message may say "Mac" or spell a shortcut by hand.

- **Shortcuts** are a placeholder in the message (`{key}`), filled by the caller: desktop `kbd(stroke)` / `label()` / `modClick()` in `apps/desktop/src/lib/keys.ts` (follows OS and the user's remaps), Rust `atlas_i18n::shortcut("cmd-shift-p")` (`⌘⇧P` on macOS, `Ctrl+Shift+P` elsewhere; key names such as `Space` come from `common_keys_*`, pt-BR `Espaço`).
- **System nouns** come from the shared terms (`common_os_your_computer`, `common_os_file_manager`, `common_os_trash`, `common_os_system_settings`, `common_os_alt_key`, `common_os_enter_key`, `common_os_menu_bar`; the `os` entries in `i18n/glossary.yaml` list each platform's wording). Reference one as `{@common_os_trash}`: the message becomes an `os` select (`mac`|`windows`|`*`) by itself, and the i18n layer passes `os`, so call sites never do. pt-BR needs "no Finder" / "na bandeja": when a preposition precedes the noun, write the whole phrase with its own `os` select instead of composing.
- A screen that exists on one platform only (macOS capture permission) may name it; mark the key in `meta.json`: `{ "description": "...", "platform": "mac" }`. `i18n:check` rejects glyphs and `Cmd+`/`Ctrl+` chords in catalog values, platform nouns in a message without an `os` select, and an ad hoc `isMac` / `navigator.platform` outside `keys.ts` (`IS_MAC`).

## pt-BR rules

- Glossary terms stay English: Atlas, Crew, crewmate, hostd, worktree, branch, commit, merge, pull request, deploy, prompt, token, log, build. Check `i18n/glossary.yaml` before inventing a rendering.
- Register: você. Buttons and menu items in the infinitive ("Salvar", "Abrir projeto"). Sentence case. No em dashes. No gerundism ("vou estar enviando"). Errors say what happened, then what to do.
- Brazilian, never European: tela (not ecrã), usuário, arquivo, configurações, salvar, excluir, baixar. `i18n:check` has a deny-list.
- **Plurals.** pt-BR needs `one` and `other`; CLDR puts 0 in `one`, so a `one` variant that prints the count says "0 arquivo", and `i18n:check` fails it (`pt-zero`). Add an exact zero in pt-BR ("Nenhum arquivo"): a `countExact=0` match (second selector, only in the pt-BR file; English may keep "0 files" but gets one too when it reads badly, e.g. "0 of 0 rows"). Or, when the code provably never calls it with 0, write `i18n-allow pt-zero: <why, and the call site>` in the description. Keep a default (`*[other]`) because engines disagree on large numbers; never key an arm on a number of the plural selector itself.
- Numbers, dates, lists and relative time come from `Intl` (desktop `fmt`) or are written into the message; never concatenate translated fragments into a sentence.

## Where the language comes from

One implementation, `atlas_core::lang` (CLI, TUI, hostd, desktop shell; a debug build also knows `en-XA`, below), precedence `ATLAS_LANG`, `~/.atlas/language`, `LANGUAGE`/`LC_ALL`/`LC_MESSAGES`/`LANG` (C/POSIX = English), the OS, English; any `pt*` selects pt-BR. `atlas config lang` shows it and what decided it; `atlas config lang <tag>` and Desktop Settings write `~/.atlas/language`. The desktop receives the resolved tag from Rust (a Tauri command) and never reads `navigator.language`. Mobile follows the phone.

## Layout pass in the pseudo-locale (en-XA)

Every migrated screen is looked at in `en-XA` (accented, padded 35%, wrapped in `⟦ ⟧`) and in pt-BR before its PR opens (`i18n/MIGRATION.md` step 6; why and where it exists: `i18n/README.md`, "The pseudo-locale"). It exists in development builds only: a release build, the site and `ATLAS_LANG=en-XA` on a release binary are plain English; never list it anywhere a user sees.

1. `bun run desktop:agent -- --name <you>` (debug build; a build from before en-XA existed needs `bun run desktop:build:app`), `export ATLAS_DEBUG_SOCK=...`. Never the user's app.
2. Switch: `atlas desktop debug eval 'return await window.__TAURI_INTERNALS__.invoke("locale_set", { tag: "en-XA" })'` (or Settings > General > Display language > "Pseudo (en-XA)"). Back: `{ tag: null }` follows the system, `"pt-BR"` renders Portuguese.
3. Open each screen of the batch (`debug click`, `debug eval`), `atlas desktop debug shot /tmp/x.png`. Read it: `⟦...⟧` on every string of a migrated screen; a missing `⟧` is a truncation; plain text is not extracted; brackets inside a sentence are glued pieces. Fix overflow in CSS.
4. Rust: `ATLAS_LANG=en-XA target/debug/atlas <command>` (debug build only), 80 columns.
5. `bun run i18n:pseudo -- --print <area>` prints one area's pseudo text if you need to read it without an app.

## The ratchets (text that must not spread)

`i18n:check` also flags hardcoded user-facing text (Svelte, Rust `println!`/`bail!`), spelled shortcuts, ad hoc platform checks and flagged phrases in existing docs. These are **ratchets**: they judge your change, not a snapshot.

- **The baseline judges every file, in every mode**, touched or not: more offenders than the baseline line allows fails (with `file:line`), and so does a line above the real count (run `bun run i18n:fix`). In a git checkout the files you touch also report what you **added** (the offenders at the merge-base are counted with the same detector). Old offenders at their baseline are fine; moving them is fine; a renamed file is allowed what its old path was (`i18n:fix` moves the line). A new screen must be written with message keys: there is no way to snapshot it.
- Fix a new finding by using a message key (or `// i18n-ignore` / `<!-- i18n-ignore -->` when it is not for users). Never raise `i18n/hardcoded-baseline.jsonl` to make it pass: a raised count fails (`baseline-grew`). `bun run i18n:fix` only lowers it (a fixed file keeps its line at 0; a local `git merge` of two branches does not conflict on the file because of `merge=union` and the smaller count of a repeated path wins, but GitHub's own merge ignores that; a count above the real one fails the check in every mode: `i18n:fix`).
- Run `git fetch origin main` before checking locally: the base is `origin/main`'s merge-base (else `main`), or `ATLAS_BASE=<ref>` when set; in CI a pull request is judged against the first parent of its merge ref and a push against the commit it replaced (resolver: `scripts/lib/base.ts`). With no usable base the baseline alone judges and the check says so. CI also runs it on every push to `main`.

## Traps that cost time

- A broken Paraglide plugin path compiles zero messages with only a warning: the desktop has a test that the compiled `m` exposes the catalog's keys.
- Paraglide `setLocale` with a custom Svelte `$state` strategy throws `state_unsafe_mutation` on the first render unless it writes only when the value changed. Keep the guard.
- The Rust evaluator does no number formatting: format numbers in Rust or avoid them in the message.
- A third-party name inside a rename sweep: never translate or rewrite external API strings (Telegram `/bot<token>/`, `is_bot`).
- Test assertions on English text run in a fixed locale; set it explicitly instead of relying on the machine's.
