# Changelog

All notable changes to Atlas (CLI, TUI, MCP server and Atlas Desktop). Versions follow [SemVer](https://semver.org); the CLI and the desktop app always ship together with the same version.

> **Atlas is in alpha.** Expect bugs and breaking changes between releases. Please [report what breaks](https://github.com/codeatlasdev/atlas/issues/new). Releases come in [Stable, Beta and Alpha channels](docs/versioning.md); every one of them is alpha-quality until Atlas meets the general availability criteria there.

## [Unreleased]

### Added

- **Linux: `debug record`, the live mirror and Atlas Lab work on agent instances ([#282](https://github.com/codeatlasdev/atlas/issues/282)).** The agent instances of the line below could be screenshotted but not filmed or watched. `atlas desktop debug record out.mp4 --seconds 5` (or `--until <selector>`, `--fps`) now writes a constant-rate H.264 file of the instance's window, read from its own compositor with `grim` and encoded by `ffmpeg` (install `ffmpeg` with libx264; nothing else new), and its result says how many frames were really grabbed and the longest gap between two, so a slow machine shows as fewer frames, not a faster video. `bun run desktop:mirror` serves the live page area of an instance (~30 fps while someone watches) with click and type through the bridge, and `bun run desktop:lab` serves the frontend with Vite/HMR against an invisible instance; it also generates the icon tables first (a fresh checkout failed with `Failed to resolve import "#lib/icon-data/lucide.json"`). Never on your screen or your session. Flicker sweep, selection bench, `debug hide` and gesture record/replay stay macOS only.
- **Linux: a startup and idle baseline, measured and gated in CI ([#284](https://github.com/codeatlasdev/atlas/issues/284)).** `scripts/linux-startup-bench.ts` launches the app on a private headless sway and reports start to `app_ready` (cold and warm, p50/p95), PSS/RSS of every process at idle (the app, each WebKit web process, the network process, hostd; the report names the one that dominates) and idle CPU, and exits non-zero when `app_ready` never arrives or a number is over budget. The baseline is `docs/perf/linux-startup.json`, and the "Desktop opens (Linux)" CI job runs it after the launch check.
- **The foundation for Atlas in Brazilian Portuguese: one language for the CLI, the desktop app and the site.** English stays the source and pt-BR is the first translation. The language is resolved once, in `atlas_core::lang`: `ATLAS_LANG`, then `~/.atlas/language`, then `LANGUAGE`/`LC_ALL`/`LC_MESSAGES`/`LANG` (`C` and `POSIX` mean English), then the system language, then English; any `pt*` selects pt-BR. `atlas config lang` shows the language and what decided it, `atlas config lang pt-BR` saves it, `--unset` goes back to the system, `--json` is for programs. Every surface reads one tree of small files by area (`i18n/messages/<area>/`: `en.json`, `pt-BR.json`, `meta.json`), with shared words such as Cancel or "your Mac" defined once in `common`; the CLI, the TUI and the desktop shell embed it at build time (`crates/atlas-i18n`, `t!`, the pt-BR zero case, `os` and shortcut helpers so no text says "Mac" or spells a shortcut by hand); `atlas config --help` is the first translated help, swapped into the clap tree from `ATLAS_LANG=pt-BR`. Atlas Desktop has Settings > General > Display language (Follow system, English, Português (Brasil)) that switches the running app with no reload, a shared `fmt` helper for dates, numbers and relative time (one style: "5 min. ago" everywhere), Paraglide catalogs and the first screens migrated. The site has `/pt-br/` routes, hreflang only for pages that exist in pt-BR, and `docs/pt-BR/<slug>.md` with an English fallback banner and outdated detection (`source_sha`). `bun run i18n:check` (inside `bun run check`) names missing, outdated, unused, mismatched and hardcoded strings and the writing rules of `i18n/style/`; `i18n:translate`, `i18n:fix` and `i18n:add-locale` do the rest, and translators never need an account (see [Translating Atlas](docs/contributing.md#translating-atlas)). Machine output is never translated: `atlas crew install --progress json` prints events with stable codes (`sudo.password_rejected`, `ssh.unreachable`) so Atlas Desktop can stop reading human text, and a test runs the machine commands under both languages and compares the bytes.
- **Atlas Desktop: a plain folder is a folder, and one loose file opens in a light editor ([#499](https://github.com/codeatlasdev/atlas/issues/499)).** Opening `~/Downloads` treated it as a project that was missing its `atlas.yaml` (Auto-detected, Save as atlas.yaml, Start, services, Changes and PR), and opening one `.md` to fix a line went through the whole project UI and added a project. A folder with no `.git`, `atlas.yaml` or recognised manifest (`atlas_core::project_root::is_project_root`) is now a **plain folder**: explorer, editor, search, terminals and agents, no `atlas.yaml` prompt, no Start, services, Activity or Machine, "Not a git repository" in Changes; **Use as project** (a flag on the sidebar entry, nothing written to the folder) gives it the full UI. A text file with no project above it (`atlas notes.md`, Finder **Open With** for `.md`/`.markdown`/`.txt` through the new `fileAssociations` and `RunEvent::Opened`, a drop on the window) opens in the **light editor** with no project, no worktree, no language server and no git, and a Markdown bar (bold, italic, heading, lists, link, preview); **Open folder** and **Open as project** continue in the full app. Quick Open in a plain folder walks it (`atlas_core::filelist`: `.gitignore` honoured, dependencies, build output and dot folders skipped, 20,000 files and 2 s at most, off the UI thread, cached until the watcher reports a change). **Open any file with Atlas on macOS, Windows and Linux**: Atlas is offered in Open With for text, source and data files and for folders and never becomes the default (macOS: `fileAssociations` with `LSHandlerRank` `Alternate` for `public.text`, `public.source-code`, `public.data`, `public.folder` and the rest; Windows: per-user `HKCU` "Open with" keys and an **Open with Atlas** folder entry written by the installer and removed on uninstall, no extension key touched; Linux: `MimeType=` and `%F` in the `.desktop` file of every package from one template), and a second Open With goes to the running window. The light editor reads and writes its file in the app process (`loose_fs.rs`, atomic write) instead of through hostd. Not verified on a real OS: the three registrations (they need an installer or bundle on each system) and the open times. Tests: `project_root` (real temp folders), `filelist`, `loose_fs`, `scripts/open-with.test.ts` (plist, `.desktop` and NSIS contracts), `cmds::projects` (view kind, promote, `locate`, real-serialization fixtures), `ProjectHeader.test.ts`, `ctl.test.ts` (a loose file registers nothing), `LooseEditor.test.ts`, `markdownFormat.test.ts`. See [docs/desktop.md](docs/desktop.md#plain-folders).
- **Add a crew server offers the servers you already have in `~/.ssh/config` ([#502](https://github.com/codeatlasdev/atlas/issues/502)).** The setup screen was a free-text `ubuntu@my-server.com` field plus a port, so a server you reach with `ssh prod` had to be retyped (and its key, port and jump host were lost). A searchable picker now sits above the field: each row is the alias and where it goes (`prod · deploy@203.0.113.7:2222`), typing filters on all of it, arrows and Enter pick, and picking fills the address (`deploy@prod`) and the port. The address keeps the alias, not the host name, so ssh goes on applying that entry's `IdentityFile`, `Port` and `ProxyJump` to every call Atlas makes. The list comes from the new `ssh_hosts_list` command (`atlas_core::ssh_config`): it reads `~/.ssh/config` and its `Include`s (globs, relative to `~/.ssh`) for the `Host` names, skips wildcard and negated patterns and `Match` blocks, then asks `ssh -G` for each one (eight at a time, 5 s each, off the main thread, no connection) what ssh would really use, so `Host *` defaults and `Match` rules are ssh's own. No file, an unreadable one or no `ssh` leaves just the free-text field, with no message. Guarded by parser tests on a realistic config (Include with globs, several patterns on one line, quotes, comments, `Host *`, `Match`), a test against the real `ssh -G`, a parse test on real `ssh -G` output, and a component test of the picker on the real serialization of the Rust type.
- **Agent guards: AI agents can no longer write outside their worktree, push to `main`, force-push, merge, stash or delete branches and tags.** The rules were prose in `AGENTS.md`; six times in one day agents wrote into the main checkout through relative paths, and a shared `git stash` applied one agent's work in another's worktree. One decision function (`scripts/lib/agent-guard`) now answers every tool call with allow or a refusal that names the fix (`refused: /…/atlas/crates/x.rs is in the main checkout …; use the absolute path under your worktree: …`). It is wired for Claude Code (`.claude/settings.json`), Codex (`.codex/hooks.json`) and omp (`.omp/extensions`), and as a `pre-push` git hook (`scripts/git-hooks`, installed by `scripts/setup.sh` through `core.hooksPath`, which also ends the lefthook warning on every commit) that refuses `main`, `release/*`, force-pushes and ref deletions whatever tool pushes. A maintainer lifts a rule for a session with `ATLAS_MAINTAINER_OK=<action>`; an agent cannot set it. See [Agent guards](docs/contributing.md#agent-guards).
- **`bun run pr:merge <pr>` merges a pull request only when it is safe, and closes exactly the issues it links.** A hand-typed squash body closed the wrong issue (the squash of #509 said `Closes #503`, #509 links #501 and #504; #503 was closed by the wrong commit). The script refuses a branch behind `main`, a head that is not the tip of its branch, a head whose own `ci.yml` run has not concluded `success` (never the status rollup), and a title that is not conventional; it writes the squash message itself (`<title> (#N)`, `Closes #M` per `closingIssuesReferences`, your `Signed-off-by` unless it is a placeholder) and merges with `--match-head-commit` only for an active member of `atlas-maintainers`. `--dry-run` and `--json` give the decision and the body. A new workflow, `Closing keywords`, runs on every push to `main` and fails, commenting on the pull request, when a squash commit closes an issue its pull request does not link. See [CONTRIBUTING.md](CONTRIBUTING.md#pull-request-flow-and-who-merges).
- **Add a crew server works the same on macOS, Linux and Windows: SSH key or password, chosen up front ([#517](https://github.com/codeatlasdev/atlas/issues/517)).** The setup screen assumed a Mac ("your Mac's SSH key"), never showed which key it used, offered a password only after one exact ssh error, and its password helper was a `#!/bin/sh` script that Windows cannot run. Now the form asks **Sign in with** **SSH key** or **Password** before anything runs. With the key it shows the key `ssh` will use for that address (a `~/.ssh/config` alias has its own) and **Choose another…** opens a file picker; the picked key goes to every ssh call of the install (`atlas crew install --identity KEY`, also `atlas crew browsers install|status`) and is kept in `crew-servers.json` so the tunnel, the mobile relay and Settings use it after a restart. With the password it signs in once, adds this computer's public key to the server (creating a key when there is none; a key without its `.pub` works) and installs with the key, so later connections need no password. The password never touches argv, the environment or disk: `ssh` runs Atlas Desktop's own executable as its `SSH_ASKPASS` program, which fetches the password from a one-shot local endpoint (a Unix socket in a private directory, a named pipe on Windows) and answers only a password prompt. Every failure says what to do next (a refused key names the key and offers the password or another key; a server that is down, silent, misspelled or with a changed host key says so; sudo that wants a password asks for it; the CLI's own `hint:` line is shown when it has one) with the tool's last line under **Details**. On Windows a missing OpenSSH Client is named up front with the command to add it. The install checklist gained a first **Signing in** step and says what each step does and how long it takes, and the copy of the whole crew onboarding says "this computer", never "your Mac". The onboarding shell keeps Back and the one primary button in a fixed footer outside the animated step (same rectangle on every step and state, measured by `scripts/onboarding-footer-rects.sh`), the form uses the kit TextField and SegmentedControl, the connect art shows this computer, the SSH link and the server lit phase by phase (and red where it broke), and every step links to its section of the crew docs (one map, `docsLinks.ts`, checked against the headings of `docs/crew.md`; failures link to the new "Add a crew server fails" troubleshooting rows). See [Atlas Crew](docs/crew.md#add-a-crew-server-in-atlas-desktop).
- **`bun run i18n:extract` moves hardcoded text of Svelte components into the catalog, and `i18n/MIGRATION.md` plans the move of the rest.** About 2,200 strings of the desktop app and the site were still typed into components. The tool replaces text and attributes (`aria-label`, `placeholder`, `title`, `label`...) with `m.<key>()`, writes the English and a description, reuses the shared `common` messages, never invents a pt-BR, and lists what it will not touch (plurals, text joined to an expression, shortcuts, `.ts` modules) with file and line; on the real desktop code a dry run converts 1,803 of 2,213 strings. Rust gets a worklist instead of a rewrite. The plan splits the work into batches by area, with the quality loop for an AI-translated first version.

### Changed

- **One list of coding agents for the CLI, Atlas Desktop, hostd and Atlas Mobile.** The built-in agents (omp, Claude Code, Codex, OpenCode) were typed nine times across Rust, TypeScript and Dart and the copies disagreed on OpenCode. They are now one file, `crates/atlas-core/data/agents.json` (id, label, binary, hooks setup name, launch flags, capabilities); Rust embeds it, the desktop imports it and the phone reads a Dart file generated from it, with tests that fail when a copy is stale or a list is typed again. OpenCode is a first-class agent everywhere: hostd's hooks check and Atlas Desktop's prompt now cover it (`atlas setup opencode`), the phone shows its mark, its name and its sign-in row. It is still not offered for AI commit messages (no tools-off one-shot run is verified), and Settings → Git no longer lists agents that cannot write a message (OpenCode, custom agents) as choices that did nothing. The crew pickers and the onboarding list the agents in one order (omp, Claude Code, Codex, OpenCode).
- **One map from changed paths to checks: `bun run check`, `bun run check:changed` and CI's plan job read the same file, and the gate runs what CI runs.** The path-to-check mapping lived three times (the `check` chain, `scripts/check-changed.ts` and `scripts/ci-paths.sh`), and `bun run check` missed two checks CI required: jscpd duplication (`bun run dup`, at most 1.5%) and the site type-check and build. `scripts/checks/map.ts` now holds areas with path globs and the checks of each area; `bun run check` runs every check, `check:changed` the areas the change touches (a path no area claims runs everything), and `scripts/ci-plan.ts` replaces `scripts/ci-paths.sh` as the plan job, so the `area=true|false` outputs that gate the jobs of `ci.yml` come from the same map. `scripts/checks/map.test.ts` fails, naming the line to add, when CI gains a job, a gated area or a check command the map does not list (and mutation-tested against a new job and a new step). The diff base is one resolver, `scripts/lib/base.ts` (merge base with `origin/main`; a pull request's merge-ref first parent; a push's `before`; CRLF-safe; no path comparisons, so Windows short names cannot break it; no base means everything runs), tested against real git repositories. `bun run check:changed --dry-run --json` prints what would run and why (base, changed files, areas on and the paths that turned them on, commands, and the checks only CI can run), `bun run check --json` lists the gate. Also: the push-relay job now runs only when `services/push-relay` or its script changes, the `scripts` job when scripts, the changelog, packaging or the workflows change (not on every desktop change), a change to `CHANGELOG.md` now reaches the scripts tests that lint it, and the plan job fails the run when it cannot plan (it used to leave every output empty, which skips every job). The `affected:` plugin of `atlas.yaml` is now `bun scripts/check-changed.ts --json --stdin`. See [contributing](docs/contributing.md#the-gate).
- **The Signed-off-by check refuses placeholder identities, and release commits are signed off.** A commit authored or committed as a placeholder (an email on `example.com`, `.test` or `.invalid`, a host name such as `you@MacBook.local` or `localhost`, a template name like "Your Name" or "First User") now fails the required `Signed-off-by` check on pull requests even when it carries a sign-off: two such commits ("First User <first@example.com>") reached 1.5.0-alpha.26 and could not be credited. `bun run release` now signs off its own `chore(release)` commit, which 1.5.0-alpha.24 to alpha.26 lacked (it goes in through the maintainer bypass, so the check never saw it). See [CONTRIBUTING.md](CONTRIBUTING.md#developer-certificate-of-origin-dco).
- **macOS releases are Developer ID signed and notarized, so the firewall stops asking again after every update.** The `atlas` CLI, `Atlas.app` and the `.dmg` are signed with CODEATLAS LTDA's Developer ID (hardened runtime, secure timestamp) and notarized by Apple; the app and the dmg are stapled, a bare CLI binary cannot be (Gatekeeper checks it online once). With the macOS application firewall on, an ad-hoc identity is the binary's hash, so every release made `atlas hostd` (which opens the phone gateway while a phone is paired) ask "allow incoming connections" again, and privacy grants (Screen Recording, Input Monitoring) had no stable identity to attach to; a Developer ID identity is the same across updates, and a downloaded `.dmg` opens without Gatekeeper's warning. `release.yml` imports the certificate into a temporary keychain it deletes, signs, notarizes and then checks the real files (`codesign --verify --deep --strict`, `spctl`, `stapler validate`, Team ID, hardened runtime, entitlements) before packaging. It switches on when the six repository secrets exist (`scripts/macos-signing-secrets.sh` sets them from the certificate Apple issues and `~/.config/stores/apple.env`, printing no value); without them, as on a fork, the build stays ad-hoc signed and says so, and some secrets but not all fails the build. The hardened runtime needs one entitlement in the app, `com.apple.security.device.audio-input` for Settings › Capture › Microphone, and none in the CLI (each exclusion is justified in `crates/atlas-desktop/Entitlements*.plist`). See [Releasing](docs/release.md#macos-signing-and-notarization) and [Installation](docs/installation.md).
- **Dates and times moved from `chrono` and `chrono-tz` (unmaintained, RUSTSEC-2026-0543 and RUSTSEC-2026-0555) to `jiff`, and crew schedules from croner 2 to croner 4 ([#540](https://github.com/codeatlasdev/atlas/issues/540)).** Every timestamp Atlas writes keeps its exact bytes (`+00:00` or `Z`, 0, 3, 6 or 9 fraction digits, numeric offsets), and the files older builds wrote still load; contract tests pin them. Time zones are bundled in the binary as before. Schedules answer the same except around a clock change, where croner 2 was wrong: a job that runs every hour or minute now runs through the repeated hour of a fall-back night instead of skipping it, a trigger created in that hour no longer fires on every tick, `1W` stays inside its month, and a list or step that lands in a spring-forward gap skips that slot. A cron saved with a `?` in the minute, hour or month field (`? * * * *`, croner 2 read it as `*`) keeps running as the same schedule; one the new parser still refuses (a `+5` minute) is kept as saved, listed as invalid with the parser's message in Atlas Desktop and on the phone, never fires, and does not block editing the others. A custom clock time in a log filter that falls in a spring-forward gap has no answer (as documented), and in the repeated hour it is the first of the two. `chrono` still comes in through `iroh` on Windows (`wmi`); Atlas's own code no longer uses it.
- **`AGENTS.md` is a short map, and the repo's skills load on demand in Claude Code, Codex and omp.** `AGENTS.md` went from 18 KB, more than half of it the desktop-debugging manual, to under 8 KB; that manual is now the `desktop-debug` skill, and platform, runtime and desktop-shell rules sit in `AGENTS.md` files that load when you work in that crate. Claude Code reads skills only from `.claude/skills`, so that is now a link to `.agents/skills` (the one source Codex and omp read directly). `bun test scripts` fails when `AGENTS.md` passes 8 KB, names a skill or path that does not exist, or `.claude/skills` stops being that link.
- **A release is not published until its Windows and macOS files have been run ([#312](https://github.com/codeatlasdev/atlas/issues/312)).** `release.yml` built `Atlas-Setup.exe`, the NSIS installer, the `.dmg` and the `.app` and published them unopened (Linux had been opened since #283). Two new jobs run them on native runners before `publish`: Windows installs `Atlas-Setup.exe` and the NSIS installer silently, opens the installed app, and uninstalls; macOS mounts the `.dmg`, verifies the app's signature and opens the app from the `.dmg` and from the `.app.tar.gz`. A file that does not match its checksum, does not install, does not open a window or leaves an error in `app.log` stops the release.

- **The release workflow sets up its toolchain in one place, and the manifest lists only what is built ([#317](https://github.com/codeatlasdev/atlas/issues/317)).** `release.yml` repeated the Rust install six times, the apt block five times and `SOURCE_DATE_EPOCH` nine times; they are now one composite action (`.github/actions/release-toolchain`) that every build job calls, so a build cannot get another epoch or toolchain than its siblings. `manifest.json` no longer lists `x86_64-apple-darwin` and `universal-apple-darwin`, which no job ever built; a test pins its platforms to the `atlas-<target>` artifacts the workflow uploads.

- **Big repositories: search results, the file tree and the Source Control list only draw what is on screen, and Go to file ranks 100k files in under 10 ms ([#308](https://github.com/codeatlasdev/atlas/issues/308)).** A search with 2000 matches put 2200 rows in the page, a folder with 5000 files 5000 rows and a checkout with 1500 changes 1500 rows (each with an inline icon), so opening them, scrolling and every status refresh scaled with the size of the repository. They are now windowed lists (the same one the diff, the transcript and action logs use): about 25 to 35 rows in the page whatever the size, and the keyboard still reaches every row (search: ↑ ↓ ← → Enter as before; file tree: arrows, Home, End, F2 and the context-menu key; Source Control: ↑ ↓ Home End between entries). Go to file used to build an item with its icon for every file and score, sort and cut all of them on every key (about 160 to 210 ms per key at 100k files); it now builds an index once per file list, a longer query only looks at what the previous one matched, and only the best 80 are kept: 100k files, typing "controller" one letter at a time, 8 ms p95 per key (compute only) on the same machine.
- **Changes view: untracked files are read eight at a time, one round trip each ([#310](https://github.com/codeatlasdev/atlas/issues/310)).** `git_diff` read every untracked file one after the other with an `fs_stat` and then an `fs_read` (two round trips, and the project registry loaded from disk for each), so a checkout with hundreds of new files made the Changes view wait for hundreds of serial round trips, worst on an SSH host. It now reads up to eight at once, with a single `fs_read` of 512 KiB + 1 bytes per file (a bigger file is still shown as binary), keeping the order of `git ls-files`. 300 untracked files behind a 5 ms round trip: 4.18 s before, 0.31 s after; against a local hostd 155 ms before, 78 ms after.
- **The desktop frontend has a startup budget, checked in CI ([#288](https://github.com/codeatlasdev/atlas/issues/288)).** Nothing limited what the app downloads before the shell shows, and the "heavy views are lazy" rule in the docs was not enforced. `bun run bundle` (part of `bun run check` and of the frontend CI job) builds the app, takes everything the entry chunks and the main route load statically and fails when its gzip size passes `apps/desktop/bundle-budget.json` (today 1077 KiB of JS and 78 KiB of CSS) or when CodeMirror, xterm, yaml, marked, prettier or echarts become reachable from it; the budget only ratchets down. The check found that the crew chat already drags CodeMirror and `marked` into startup (listed as known violations with their reason), and xterm's stylesheet, which the shell imported eagerly, now loads with the terminal.
- **Editor: typing in a big file no longer copies the whole file on every key ([#309](https://github.com/codeatlasdev/atlas/issues/309)).** Each keystroke ran `doc.toString()` plus the save policy over the entire document (two full copies of a 2 MB file, about 7 ms a key in the tests); the dirty flag now comes from comparing the CodeMirror document with the one last saved (shared structure is skipped, so it costs what you changed, about 0.8 ms a key). The text is copied only when you save, when the file changes on disk and when a Markdown, SVG or data viewer shows it. Dirty, autosave and conflict behave as before; one thing is better: when someone else writes exactly what your buffer says, the buffer is now clean and that text is the new baseline (it stayed marked as edited).
### Fixed

- **`atlas desktop` on arm64 Linux says there is no Atlas Desktop for it, instead of a download error ([#268](https://github.com/codeatlasdev/atlas/issues/268)).** The release carries only the CLI for aarch64 Linux (crew servers), but `atlas desktop` asked for `Atlas-<version>-aarch64-unknown-linux-gnu.AppImage`, which was never built, and failed with a 404 and no explanation. It now stops with "Atlas Desktop is not published for aarch64 Linux yet", what the release does have and the releases link, and `atlas update` leaves an app you installed yourself (`--from`) alone instead of failing on its download. `manifest.json` lists a desktop asset only for the platforms that have a build, and a test keeps that list and the one `atlas desktop` checks the same.
- **Linux: no more `Gtk-CRITICAL gtk_widget_get_scale_factor` on every start of Atlas Desktop ([#426](https://github.com/codeatlasdev/atlas/issues/426)).** On Wayland with no tray host on the bus, `libayatana-appindicator` fell back to a GTK status icon that has no widget there and GTK printed the assertion at each launch. The tray icon is now created when a host is on the bus (at start, or later when a panel or the GNOME AppIndicator extension appears) instead of before; X11 keeps its legacy-tray fallback. The Linux launch check also read the wrong stderr since #347 (the app writes GTK's output to `~/.atlas/desktop/stderr.log` when it is not on a terminal), so it saw none of it; it reads that file now and no longer allow-lists the assertion.
- **`atlas deploy` never picks a release id the host already has.** Ids have one-second resolution, so two deploys of one commit within a second collided ("release exists"), and a client clock behind the host's made the new release sort before older ones (ordering goes by id). The timestamp is now the later of the clock and one second after the host's newest release ([#315](https://github.com/codeatlasdev/atlas/issues/315)).
- **Startup: the app runs your login shell once, not twice ([#285](https://github.com/codeatlasdev/atlas/issues/285)).** Every launch started two interactive login shells (`-ilc`, which reads your whole rc file) to learn your environment: the launch probe and, because it forced a second run, the first command that needed `PATH`. With a slow rc file (nvm, a hanging prompt) that doubled the CPU the launch spent and the time before the first terminal could start. The first probe now serves every caller waiting for it. hostd, which outlives the app and also serves the CLI and phones, still probes once for itself.
- **Adding or removing a crewmate no longer fails when another program holds the user database lock.** `useradd` and `userdel` refuse with "cannot lock /etc/passwd; try again later." while something else edits the accounts (an apt run, another `useradd`); the crew server now tries again for about 3 seconds before reporting it. Any other failure still stops at once.
- **Go to symbol (⌘⇧O) and the breadcrumbs list the symbols of the whole file, not only of its first kilobytes.** The outline read the syntax tree a state was created with, which CodeMirror parses within a small time budget; it now finishes the parse first (up to 200 ms, kept for later calls). The same bug made a test of the outline fail on a loaded CI runner.
- **The first install on a server this computer never connected to no longer fails with "Host key verification failed" ([#517](https://github.com/codeatlasdev/atlas/issues/517)).** The install's ssh calls run under `BatchMode`, which cannot answer ssh's "are you sure you want to continue connecting?", so with the SSH key method a first-time user's very first call was refused. The form now makes one first contact before the install that records an unknown host key (`StrictHostKeyChecking=accept-new`) and still refuses one that changed, naming the command that forgets the old one. The reconnect error "SSH refused this Mac's key" now says "this computer's key" on every OS.

## [1.5.0-alpha.26] — 2026-11-16

Atlas is in **alpha**: expect bugs and breaking changes. Please [report what breaks](https://github.com/codeatlasdev/atlas/issues/new).

**The crew release.** Atlas Crew runs your agents (omp, Claude Code, Codex, OpenCode) around the clock on a Linux server you own, and you can run all of it from the phone with no computer on: pair the phone straight to the crew server (`atlas crew pair`), send tasks with images, answer approvals and an agent's questions, sign an engine in, pause, cancel. UI work has to prove itself with captures checked in WebKit and Chromium before it can be done, and guards refuse an agent that weakens tests or invents references. Installing a crew server now checks everything it needs up front, waits for the server to answer, keeps a rollback, and works behind a proxy, offline, with a sudo password and on another SSH port. Under it, a round of hardening: a cancel is final, a crash or a bad byte no longer loses the task log, an agent's records are never overwritten by the runner, a hung `git` blocks no one, and the phone tells you when the computer's Atlas is too old instead of failing every request.

Since this version's first notes, per-crewmate isolation has been run on a real systemd server: the end-to-end test found ten things that kept it off, all fixed, and four reviews closed every way found for one crewmate to reach another or the crew user. **Re-run `atlas crew install` on every crew server** to turn isolation on. Atlas Desktop on Linux had a first-user pass: one title row and no menu bar; links, Open in editor and Reveal that work; sounds without an AAC decoder; an Arch package that starts; agent instances that stay up. Before a release, every Linux package is now installed and opened in Arch, Fedora, Ubuntu and Debian containers. The terminal host has deadlines and recovers when it falls behind, a dead web process no longer leaves a blank window, and crash reports and the diagnostics bundle are redacted and complete. Atlas Mobile asks for every permission in context, with a reason and a way forward, launches in one colour from the icon to the first screen, and builds on Flutter 3.50.

- **Agents no longer leave browsers, dev servers and caches behind, and Spotlight stays out of Atlas worktrees** ([#127](https://github.com/codeatlasdev/atlas/issues/127)). Everything Atlas starts (services, actions, interactive sessions, every hostd terminal) belongs to a session, and each root is recorded with its owner's pid **and start time** in `~/.atlas/hygiene`. On Linux every descendant carries `ATLAS_SESSION`, which survives a daemonize (`setsid`, double fork). macOS and Windows cannot read another process's environment, so there the owner records who runs under each root every 2 s and a grandchild seen below its root is still known after it daemonizes; a process that forks and detaches between two records (under about 2 s) escapes there, and `doctor --hygiene` says so. Stopping a service, finishing an action or closing a terminal ends the session's whole tree (SIGTERM, short grace, SIGKILL, exact pids, start time re-checked before every signal; never a group, a negative pid or a port); if the owner itself dies, hostd reaps the orphaned tree within 10 s. Directories Atlas registers for a session (temp, browser profiles, caches) have a size cap: a dead session's directory is deleted whole and one over its cap loses its oldest entries first, so repeated runs do not grow the disk. **`atlas doctor --hygiene`** shows orphaned tagged processes, disk per project (`target/`, `node_modules`, `.logs`, worktrees), registered dirs and, on macOS, heavy folders Spotlight indexes; it only looks unless you pass **`--fix`**, which ends the orphans, frees what Atlas owns and never removes `target/`, `node_modules`, worktrees or any file Atlas did not create. The same report and fix are in **Settings > Workspaces > Hygiene** and the new look-only MCP tool `atlas_hygiene`. On macOS every worktree root Atlas creates and every build or cache dir it registers gets an empty `.metadata_never_index` file (a Mac froze while Spotlight indexed several fresh worktrees' `target/` at once); `doctor --hygiene` lists the worktrees whose `target/` or `node_modules` are still indexed and `--fix` adds the marker, nothing else. The registry is shared by every `atlas dev`, hostd and the desktop, so a sweep never deletes a directory younger than 60 s or one whose owner still runs, refuses to register `/`, a relative path or your home, and never recreates a registry folder that was removed (a hostd whose dir is deleted exits instead of bringing it back).
- **Atlas Desktop shows why the machine is slow and what each agent runs** ([#129](https://github.com/codeatlasdev/atlas/issues/129)). - **A new worktree starts warm instead of cold** ([#130](https://github.com/codeatlasdev/atlas/issues/130)). Before `worktree.setup` runs, Atlas clones the main checkout's `node_modules` and `target` into the new worktree by copy-on-write (`clonefile(2)` on APFS, `FICLONE` on Linux reflink file systems), so `bun install` and `cargo build` only do the difference instead of rebuilding 2 to 4 GB and about 100 000 files per worktree. `worktree.seed: [node_modules, target]` picks the directories (omitted: detected from `package.json` and `Cargo.toml`; `[]` turns it off). A Python virtualenv is never cloned (it is not relocatable: its scripts hold the main checkout's absolute path, so the clone would keep running the main checkout's interpreter); a listed directory with a `pyvenv.cfg` is refused with a note, so recreate it in `setup`. Writes in the worktree never reach the main checkout (it is a clone, not a hardlink). Where the file system cannot clone (another volume, ext4, Windows, SSH hosts) the directory is skipped, never copied in full, and the progress line says so. Seeded `target` and `node_modules` get `.metadata_never_index` on macOS. A cloned `target/` is safe for Cargo: its fingerprints include the workspace path, so the worktree's own crates are rebuilt and registry dependencies are reused. The seed time shows in the progress line and, with the Setup time, in a toast when Setup ends. The planning and the clone live in `atlas_core::seed` and `atlas_core::sys::clone_dir`.
- **Worktree setup restores cached builds and installs from one package store** ([#130](https://github.com/codeatlasdev/atlas/issues/130)). A `{{action: Build web}}` step in `worktree.setup` runs that action through the task cache: a new worktree with the same input bytes restores the outputs instead of rebuilding (an unknown action name is a config error). While `setup` runs, bun and pnpm projects install from one machine-wide store under `~/.atlas/pkgstore` (`BUN_INSTALL_CACHE_DIR`, pnpm `store-dir`; npm and yarn untouched, your own store variable wins, `worktree.package_store: false` opts out). `cargo test -p atlas-cli --test worktree_fast_start` measures a fixture worktree: cold 1.68 s, warm 47 ms. See [docs/configuration.md](docs/configuration.md#cached-steps-in-setup).
- **A machine-wide queue for heavy jobs: many agents, one machine, no overload** ([#124](https://github.com/codeatlasdev/atlas/issues/124)). `atlas run --heavy [--label X] -- <cmd…>` runs a build, test suite or bench through a queue shared by every project, worktree and agent on the machine: at most N jobs run at once (default `min(cores / 2, GB of memory / 8)`, at least 1, so 3 on a 12-core 24 GB Mac; `ATLAS_HEAVY_SLOTS` or `heavy.slots` in `~/.atlas/config.json`), the rest wait in arrival order and start the moment a slot frees, after the 5-minute load is below `ATLAS_HEAVY_MAXLOAD` (default `0.75 * cores`) and at least `ATLAS_HEAVY_MINMEM` percent of memory is free (default 20, `heavy.min_mem_pct`; macOS `kern.memorystatus_level`, Linux `MemAvailable`, Windows `GlobalMemoryStatusEx`). A job's environment caps build parallelism (`CARGO_BUILD_JOBS`, `UV_THREADPOOL_SIZE` = `max(2, cores / slots)`) unless you set it. Output and exit code pass through, Ctrl-C reaches the command, and a job that is killed frees its slot at once (slots are OS file locks under `~/.atlas/heavy/`, so nothing goes stale). `atlas heavy status [--json]` and the read-only MCP tool `atlas_heavy_status` list who holds the slots and who waits, with ETAs from the average of the last runs of the same label. In `atlas.yaml`, `heavy: true` on an action (and `deploy.build_heavy: true`) routes it through the queue; `scripts/heavy.sh` is now a thin wrapper over `atlas run --heavy`. Agents should run heavy commands this way (the `atlas` skill says so). Atlas Desktop shows the queue in the Activity drawer.
- **A service whose port is held by a process Atlas did not start now says who holds it.** Before a start, Atlas asks the OS (read-only: `lsof` on macOS, `/proc` on Linux, `GetExtendedTcpTable` on Windows) who listens on the service's port. The framework's own message stays in the log. Atlas never ends a process because of its port: the message is advice for you to act on. A holder from this project's own previous run (`.logs/.pids`) is not a conflict; it is cleaned up as before. The conflict clears on its own once the holder exits ([#133](https://github.com/codeatlasdev/atlas/issues/133)).
- **Services that are "running" but hung or not usable now say so** ([#132](https://github.com/codeatlasdev/atlas/issues/132), [#136](https://github.com/codeatlasdev/atlas/issues/136)). A live process that stops answering its `health`/`port` probe turns `unhealthy` (not `failed`) after `failure_threshold` misses (default 3) of `health_timeout` seconds each (default 2), with since-when and its last log lines; `on_unhealthy: restart` also restarts it (default `notify`). An optional `ready:` probe (`http` path/URL + expected `status`, or a `command`) turns a service whose liveness passes but readiness fails `degraded`, with the probe's error; so does the same error line repeating 3 times in 60 s (numbers/timestamps normalised), clearing when it stops. `atlas_status`, the status file, `atlas dev --status` (READY column), the TUI and Atlas Desktop show both; `atlas_wait_ready` waits for `running` and, on timeout, returns the failing probe's message or the hang context. Without the new config a live service that stops answering is now `unhealthy` instead of `failed`. Not included: the Node/Bun event-loop-lag preload.
- **Memory budgets, trend and leak detection per service** ([#131](https://github.com/codeatlasdev/atlas/issues/131)). `memory_warn: 1.5GB` is a soft budget under `max_memory`: over it for two samples in a row (~10 s) the service turns `degraded` with the reason (`using 2.1 GB, over memory_warn 1.5 GB`), nothing is killed, and it returns to `running` by itself; a failing `ready:` probe or a repeating error outranks it. `on_memory_max: restart | notify` decides what `max_memory` does (`restart` stays the default: alert + restart, 3 per run, then `failed`; `notify` raises one alert and leaves the service running and `degraded`). Atlas keeps the last hour of each service's process-tree memory (one sample per 5 s), derives a `rising`/`flat`/`falling` trend, and flags a **suspected leak** (`leak suspected: +600 MB over 12 reloads`) when memory only grows from one reload or restart to the next. It shows in the sidebar, `atlas dev --status`, the Atlas Desktop card, and as `memory_rss`, `memory_trend`, `memory_trend_mb_min`, `budget_state` and `memory_leak` in the status file and MCP `atlas_status`; the new MCP tool `atlas_metrics {service, last?}` returns the series so an agent can measure before and after a change without ad-hoc `ps` sampling. `atlas config check` rejects a `memory_warn` that is not below `max_memory`. See [Memory](docs/configuration.md#memory).

- **Atlas Crew: a cancel is final, also while the project downloads ([#292](https://github.com/codeatlasdev/atlas/issues/292)).** The runner kept its own copy of a task and wrote it back (`queued`, `preparing`, then `running`) over the `cancelled` the owner had stored, so a task cancelled while its repo was cloning, or while it waited for a GitHub login, still started its agent. The store now refuses a runner write over a cancelled task, the checkout stops the moment the store says cancelled (its `git` processes are killed), and nothing starts an agent for a task the store has cancelled, terminal or engine alike.
- **Atlas Crew: a hung `git` blocks no one, and the server caps its agents ([#296](https://github.com/codeatlasdev/atlas/issues/296)).** Every `git` call of a checkout now has a 120 s deadline and is killed with everything it started (a stalled clone used to hold one global lock, and with it every crewmate's task, until the 2 h task cap, and a cancel could not reach it); the lock is per repo, so two projects on different repos check out at the same time. The server runs at most `max_agents` agents at once (`crew_settings_set`, default 4); a task past that shows **server busy** instead of a bare Queued and starts when an agent ends. A task that only waits for you (a GitHub login, an action card) holds no agent slot, so it never delays another crewmate. A per-agent memory cap (cgroup / `systemd-run --scope`) is not part of this change: it only exists on Linux and cannot be tested safely off a Linux crew server.
- **Atlas Crew: the audit log could show an agent acting before its task started.** The runner recorded `task_started` only after spawning the agent, so a fast agent's first tool call was audited first. The task is now recorded as running and audited as started before the agent exists; if that cannot be stored, the agent is not started at all (it used to start and then be killed).
- **Atlas Crew: the guards read their diff the same whatever your git config says ([#333](https://github.com/codeatlasdev/atlas/issues/333)).** With `diff.mnemonicPrefix` or `diff.noprefix` set, the guard misread paths (`c/`, `w/`, no prefix) and a removed assertion or a deleted test could go unnoticed. The guard now asks git for `a/` and `b/` explicitly.
- **Atlas Crew: automations no longer loop or re-fire ([#294](https://github.com/codeatlasdev/atlas/issues/294)).** Two crewmates triggering each other on `done` run one round and stop (a task remembers the crewmates that led to it; the refusal is in the audit as `chain_refused`). A file automation applies its `glob` and ignores changes inside the crewmate's own work tree. A GitHub automation writes an event to its seen file before it makes the task, and rests for 15 minutes when that file cannot be written, instead of re-firing the same event every 2 minutes. A new GitHub automation starts at the head of the feed and no longer answers the old events it still lists.
- **Atlas Crew: deleting a crewmate leaves nothing behind ([#297](https://github.com/codeatlasdev/atlas/issues/297)).** Delete now waits for the running turn to end, removes the Git worktree and the `atlas/<id>/…` branches from the shared clone, and refuses any write the turn still makes, so `crew/<id>/` is not recreated without its `crewmate.json`. `docs/crew.md` now says what the code does on a restart: a running task is resumed, not failed.
- **A mobile release can now carry Firebase config (push).** docs/mobile.md said the release workflow read `GOOGLE_SERVICES_JSON` and `GOOGLE_SERVICE_INFO_PLIST`, but nothing did: the workflow did not pass them, the Fastfile never wrote the files, the `com.google.gms.google-services` Gradle plugin was not declared (so a present `google-services.json` would have broken the Android build) and the iOS plist was not copied into the app. The two build lanes now write the files from the secrets only for the build and delete them, the plugin is declared (applied only when the file exists) and a Runner build phase copies the plist when present. Without the secrets the build is unchanged.
- **Atlas Crew: corrupt state fails closed ([#291](https://github.com/codeatlasdev/atlas/issues/291)).** A `crew.json` that cannot be parsed (a torn write, zero bytes after a crash) used to read as defaults, so a restart quietly un-paused the crew; it now keeps the crew paused (logged), is never overwritten, and `crew_resume` keeps the old bytes as `crew.json.corrupt-<unix_ms>` before it writes a fresh file. A corrupt `secrets.json` no longer loses every other secret to the next `set_secret`: the file is moved aside as `secrets.json.corrupt-<unix_ms>` and the call fails naming it. A corrupt push `tokens.json` or `telegram.json` is moved aside the same way (logged; `crew_telegram_status` adds `corrupt_aside` with the path) instead of being overwritten by the next registration.
- **Linux: the AppImage no longer opens a blank window on rolling distros ([#265](https://github.com/codeatlasdev/atlas/issues/265), [#266](https://github.com/codeatlasdev/atlas/issues/266)).** It carried the build distro's `libwayland-*` libraries, and with a newer Mesa (Arch, Mesa 26) every web process aborted with `Could not create default EGL display: EGL_BAD_PARAMETER`. Host graphics libraries are now left out of the AppImage, and the release fails if one comes back. Its environment is Atlas's own now (`packaging/appimage/apprun-hook.sh`): the `GDK_BACKEND` your session or you set is respected (Omarchy's `wayland,x11,*` runs natively on Wayland), except that NVIDIA's proprietary driver stays on X11; with nothing set it stays on X11 (XWayland) as before. `ATLAS_GDK_BACKEND` overrides all of it. The GTK theme is no longer forced to Adwaita.
- **Linux: the AppImage now carries GStreamer's plugins ([#265](https://github.com/codeatlasdev/atlas/issues/265)).** It shipped GStreamer without any plugins and looked for them in Ubuntu's `/usr/lib/x86_64-linux-gnu/gstreamer-1.0`, which other distros do not have, so media the page played could fail with `GStreamer element appsrc not found` (seen on Arch). Using the host's GStreamer instead is not possible: it needs a newer glib than the AppImage carries. Checked with real playback afterwards (see the entry above).
- **Atlas Crew: pause, cancel and the 2 h timeout now stop an engine turn and everything it started ([#290](https://github.com/codeatlasdev/atlas/issues/290)).** `crew_pause` and a task cancel only killed a crewmate that ran in a terminal; a headless `engine` turn (claude, codex, opencode, omp) went on running and spending after the task showed `cancelled`, and the 2 h cap dropped the wait without stopping the agent. Every engine turn now runs in its own process group with a cancel handle that pause and cancel fire, and on cancel, timeout or any other end the whole tree is killed, so the tool processes an agent started (omp's `bash` calls, a build) are gone too, not only the CLI. `docs/crew.md` says so.
- **Atlas Crew: a task resumed after a restart could end `failed` although its agent finished.** A new hostd started the crew (tasks resumed after the restart, schedules and triggers due at once) before its hook server had bound and rewritten the endpoint file, so an agent that finished quickly posted its `done` to the previous daemon's dead port, and its exit then recorded `failed: agent exited (code 0)`. The crew now starts only after the endpoint is this daemon's.
- **`scripts/heavy.sh` lets one heavy job run at a time again on Ubuntu 26.04.** Its fallback lock (an installed atlas without `run --heavy`, or none) was a `mkdir`, and uutils `mkdir` 0.10.0, Ubuntu 26.04's coreutils and GitHub's `ubuntu-latest` since image 20261111, tells both of two racing callers that it created the directory: two jobs ran at once in 22 of 40 tries. The lock is now a pid file the shell creates with noclobber (`O_CREAT|O_EXCL`), the same on macOS, Linux and Git Bash, with no `shlock` or `mkdir`; a stale lock is removed only if it still names the dead pid.
- **Atlas Crew: what the agent recorded on its task could be erased by the runner.** The runner keeps its own copy of a running task and writes it back on every title or step; the agent's own records (marking the task as UI work with `set_ui`, the captures it attached, an `ask_user` question) went to the stored task and the runner's next write took them back. A UI task then ended `done` without its captures, and a question could vanish from the cards. Hook routes now change the stored task in one locked step, and the runner's writes keep those fields.
- **Atlas Crew: a cancelled or paused task ended up `failed` (#324).** Cancelling a running task (or pausing the crew) recorded `cancelled` and stopped the agent. Then the runner saw the agent exit and wrote `failed: agent exited (code 1)` over the cancellation, so Telegram and GitHub heard "failed" for a task you stopped. The cancellation now stands, with its reason (`paused`).
- **A call to a terminal host that had just gone away could wait forever (#226).** The connection to hostd failed calls that were in flight when it dropped, but a call made a moment later was queued for a reply that would never come; `closed()` asked after the drop never returned either. Atlas Lab forwarding to a main hostd that was restarting hung there (a CI test hit its 180 s timeout). Both now fail at once with "hostd disconnected". Atlas Desktop could also miss the moment its local hostd connected and report it unreachable after 10 s.
- **Atlas Crew: a restart of the crew server no longer loses running tasks (#199).** An upgrade, a reboot or a crash used to mark every running task `failed` ("interrupted by daemon restart"). Now a running task goes back to the head of its crewmate's queue with the same id, marked `resumed` and counted in `restarts`: a crewmate with an engine continues its agent session, one in a terminal runs the task again. A task interrupted more than twice fails with a clear error instead of looping. Tasks waiting for you (`waiting_action`) keep waiting and can be answered after the restart, a paused crew stays paused, and an open `ask_user` question is dropped with a step that says why. See [docs/crew.md](docs/crew.md#what-survives-a-restart).
- **Atlas Crew security hardening.** The systemd unit now sets `ProtectHome=read-only` (the crew home stays writable), `MemoryMax=80%`, `TasksMax=4096`, `ProtectKernelTunables`, `ProtectControlGroups` and `RestrictSUIDSGID`; re-run `atlas crew install` to apply it. Atlas Desktop's SSH key bootstrap no longer leaves the account password in a temp file when `ssh` fails to start (the helper is created owner-only and deleted on every path). GitHub automations only fire for owners, members and collaborators (`authors`), tasks started by a GitHub or webhook automation ask for approval unless the automation sets `allow_auto` (an engine that cannot ask refuses them), an approval no longer waits 30 minutes when only an offline phone's push token could answer, a task whose state cannot be saved (full disk) now fails visibly, event text is wrapped as untrusted content, five wrong Telegram link codes invalidate the code, and the documented 20 000-character prompt limit is enforced. The docs no longer say omp always runs `auto`.
- **Terminals reported their agent as another pane** when the terminal host had been started from inside an Atlas terminal: every terminal it opened inherited that terminal's `ATLAS_PANE_KEY` and hook endpoint. A terminal's identity is now always its own.
- **Atlas Mobile showed no projects for a hostd in another directory.** The terminal host read the desktop's project list from its own directory, so a daemon started with `ATLAS_HOSTD_DIR` (Atlas Dev uses `~/.atlas/dev`) told the phone "Projects 0". It now reads `~/.atlas/desktop/projects.json`, where the desktop keeps it.
- **"Integration is off" for hooks another Atlas installed.** `atlas setup <agent> --check` now exits 2 when Atlas's hooks are there but differ from this binary's (another version wrote them), and hostd reports that as `other_version` instead of `missing`, so Atlas Mobile no longer says omp or Claude Code is off while you run Atlas Dev beside your installed Atlas. The notice now names the command that turns an integration on.
- **Crew: faster start and short replies.** omp started by a crewmate waited 25 s for a power assertion on headless servers, which delayed the first step and made every reply summary time out; it now starts in seconds and long replies are summarized again.
- **Crew: no long silent wait on a first task.** A crewmate's Git project starts downloading as soon as the project is set, a task waiting for it says "Downloading <repo>…", and a missing project folder is refused when it is set instead of failing every task.
- **Crew: automations kept each other.** Adding, toggling or removing one used to replace the whole list; the interval and webhook forms never saved.
- **Crew: the GitHub author filter did nothing for comments, issues and PRs from the events feed, and editing a GitHub automation reset it.** `gh api repos/<r>/events` carries no `author_association`, and a missing one was treated as trusted, so any stranger's issue or PR reached an `auto` crewmate's prompt. hostd now reads the association from the issue, PR or comment itself, and an event whose author cannot be resolved is retried, never allowed. Atlas Desktop and Atlas Mobile rebuilt a GitHub automation as `{repo, events}` when you saved an edit, which reset `authors` and `allow_auto` to their defaults on the server; they now hand back every field they have no control for. `pr_review_requested` could never fire (it waited for an event type GitHub does not send); it now matches the real `review_requested` event.
- **Crew setup: "Something else" waits for your text** instead of being saved as the project or role.
- **Crew: a fast agent's task failed although it had finished.** The runner started listening to the agent only after spawning it, so an agent that reported its end within the first milliseconds (a short answer, a quick check) lost that report, and its exit failed the task with "agent exited (code 0)". It now listens before the agent starts, and a status buried under a burst of other panes' events is read back from the agent's stored state.
- **`atlas deploy` no longer ships an older commit over production by accident.** Before building, it reads the commit the host is serving and compares it with `HEAD`: a downgrade is refused (with both shas and the commits that would be dropped) unless you pass `--allow-downgrade`, a diverged `HEAD` unless `--allow-diverged`, and a deployed commit this repo does not know (after trying `git fetch origin <sha>`) unless `--allow-unknown-base`. A forward deploy prints `deploying <id> (<sha>) over <deployed-id> (<deployed-sha>): +N commits`. `atlas deploy rollback` is unchanged ([#170](https://github.com/codeatlasdev/atlas/issues/170)).
- **`atlas deploy` artifacts built on macOS no longer carry Apple metadata.** Extended attributes (`LIBARCHIVE.xattr.com.apple.provenance`) and `._*` files are left out, so GNU tar on the host stops printing a warning per file and the same content hashes the same on any machine (owner `0/0`, nameless gzip header, and with GNU tar sorted names and pinned mtimes). The host driver also ignores those headers in artifacts from older versions ([#171](https://github.com/codeatlasdev/atlas/issues/171)).
- **A display wake could crash Atlas Desktop** (`wgpu error: Failed to wait for GPU to come idle before reconfiguring the Surface`, #166). Reconnecting a monitor posts dozens of screen-change events in a second and each rebuilt every terminal; a burst now causes one rebuild per terminal, after it settles. A surface that fails to reconfigure no longer panics: the terminal skips frames and retries with a growing delay, GPU errors are logged instead of fatal, and a panic while a terminal is rebuilt is reported with its cause (it was "receiving on a closed channel") and the old surface stays in place.
- **`atlas uninstall` no longer deletes your data, and lists what it does.** It used to delete all of `~/.atlas` (settings, the project list, worktrees with uncommitted work) and every line of your shell startup files that contained `.atlas`, including your own (`source ~/.atlas/env.sh`). It now removes what Atlas installed (the `atlas` command, the desktop app or only its dev link, the `# Atlas CLI` lines it added, the update cache, the terminal host's sockets after asking a running host to stop) and **keeps** settings, projects, worktrees, the channel and the omp plugin, listing both; `--purge` deletes all of `~/.atlas`, `--dry-run` lists and exits. It also finds the `PATH` line in `$ZDOTDIR/.zshenv`, removes the Linux launcher entry and icon, never deletes a fish file it did not write, refuses to run without a terminal and without `--yes`, and reports a step that failed while finishing the rest. The Windows setup passes `--purge` when you choose to delete your data.
- **Re-running the installer could downgrade Atlas or break a dev link.** `atlas install` (what `install.sh` and `install.ps1` run with the newest Stable) replaced `~/.atlas/bin/atlas` whatever was there: a newer build went back to the bootstrap Stable (stranded if the update that follows was offline), and an `atlas link` symlink was overwritten. A newer install and a link are now kept; an equal or older one is replaced. Its staging file is per process and removed when the copy fails (`.atlas-install-tmp` could be left half-written, or shared by two installers).
- **The installer's `PATH` setup lied and could skip you.** "Already set" was a substring test, so `export PATH="~/.atlas/bin-old:$PATH"` or a comment mentioning the folder left `atlas` off `PATH`; bash with no login file printed `Added to PATH [bash (no rc file found)]` as a success; a file without a trailing newline had the `# Atlas CLI` marker glued to its last line; and an `atlas.fish` you wrote was overwritten. Matching is now the exact line, a missing bash file is not reported as set, and a fish file Atlas did not write is left alone.
- **`atlas link` / `unlink` could leave you without an `atlas`.** `link` removed the release binary before creating the symlink (a symlink that could not be created, as on Windows without Developer Mode, left nothing), and after `cargo clean` a dangling link could not be relinked ("File exists"). `unlink` with no backup removed the link and told you to run `atlas install`, which no longer existed; it now keeps a plain copy of the dev build. The desktop link and unlink never delete the app or the link before the replacement is in place, and a desktop failure no longer stops the CLI from unlinking.
- **Saving the update channel could race.** The CLI and Atlas Desktop wrote the same `update-channel.tmp`; two saves at once could rename a half-written file into place. Each save now uses its own temp file and removes it when it fails.
- **Windows: `atlas install` left the old `atlas.exe` beside the new one, and `atlas uninstall` always found something to remove.** The old image is moved aside (Windows cannot delete a running program) and is now deleted right away when nothing runs it, put back if the new one cannot be placed, and only a file is ever moved aside. `atlas uninstall` took the install folder off your user `Path` whether or not it was there, so a machine with nothing installed still listed work and a second run never came back empty; it now plans that step only when the entry exists.
- **A damaged `settings.json` no longer wipes every setting.** The file was read as "no settings" when it could not be parsed (a crash mid-write, a hand edit, an editor saving UTF-16), so the next save, for example the onboarding flag, rewrote it from defaults. It is now copied byte for byte to `settings.json.corrupt` before the app saves again. Two saves at the same moment (the onboarding flag and a preference) can no longer drop one of the keys, and a shell choice goes through the same safe path.
- **The project list and `settings.json` are saved without losing concurrent changes.** Adding folders in onboarding while a pin, a worktree create or a branch switch ran could drop an entry, two worktrees created together could get the same port offset, and every writer shared one temp file name. Edits now hold one lock from read to write, temp files are unique and removed on failure, and an edit that changes nothing does not rewrite the file.
- **Onboarding could leave a blank window or show the welcome over a broken project list.** If settings could not be read the app never left its loading state (no welcome, no empty-state hero, no checklist); it now starts as a returning user and says why. If `projects.json` could not be read the welcome deck appeared on top of it and every folder you added failed; the window now shows "Could not read your projects" with the file path and **Try again**.
- **A folder named like YAML (`my: app`, `#todo`, `123`, `true`) broke its detected config.** The folder name and the detected scripts were written into the in-memory (and "Save as atlas.yaml") config without quoting, so such projects failed with "detected config is invalid" or got another name. Values are quoted only when they need it. Detected Node services also come out in a fixed order, so their ports no longer change from one launch to the next.
- **Terminals and stacks could disagree about which `atlas` CLI exists.** hostd's startup returned `$ATLAS_BIN` unchecked and accepted a directory or a half-written file at `~/.atlas/bin/atlas`, and only looked at the app's own minimal `PATH`, so a Finder or Dock launch missed a CLI in `/opt/homebrew/bin` that stacks found. One lookup now serves both: an unusable `ATLAS_BIN` or install file is skipped, and the login shell's `PATH` is tried before the app's. When none is found the message gives the installer command.
- **A terminal host that dropped the app right after connecting made it reconnect in a tight loop.** The reconnect now waits, doubling up to 10 s, and only a connection that lasted 30 s counts as healthy and resets the wait.
- **The What's new sheet and Settings rows no longer misalign or leak markdown.** The `Alpha` channel badge was drawn as a tall pill below the date and the footer's `release · following Alpha` badge sat below its text (the badge carried the class `alpha`, which is also the footer note's class, so it inherited that block's margin and border); badges are now self-contained pills tagged by `data-channel`. The release intro and each item's title now render their `**bold**` and `` `code` `` instead of showing the markers, and the "Updated to X" card shows the same text without them. In **Settings → Integrations → Agent hooks** (and every row with an icon) the logo sits next to the agent's name instead of floating in a wide first column on a wide dialog; the status text of a language server no longer wraps out of its pill and wraps under the name on a narrow dialog, versions in the update tiles never break in the middle, and the sidebar's PR/host tags truncate instead of pushing the name out.

See [Paste](docs/terminal.md#paste).

## [1.1.1] — 2026-10-12

### Changed

- **Native trackpad swipes.** Two-finger swipes over the sidebar (spaces) and over a tab group (tabs) are tracked by macOS itself, the same way Safari swipes between pages: the view follows your fingers, rubber-bands at the ends, gives a light haptic tick at the commit point, and one swipe moves exactly one space or tab. Momentum never chains into a second switch. Tab swipes now also work on tab strips that scroll. They follow System Settings → Trackpad → *Swipe between pages*; when that is off, the previous recognizer is used.
- **Instant space switching.** The spaces next to the current one stay ready in the background, so a switch shows them instead of building them, and the slide springs from where your fingers let go. Clicks and shortcuts use the same animation.
- **Error screens.** A crash in one tab or panel now shows an error card in that spot only (Retry, Close tab, Copy details, Report issue, and the stack under Details) while the rest of the app keeps working. A crash of the whole window shows a proper error page with Reload app instead of a bare "500". Errors outside rendering show a toast with Details, and repeats are grouped.

### Fixed

- Opening an SVG file crashed the app with a "500" page (an update loop in the SVG preview). Spaces with an SVG tab open crashed when you switched to them.
- Update checks and *What's new* failed with `403` once GitHub's unauthenticated API limit (60 requests per hour per network) was used up. Atlas now reads the latest version from the release page and the notes from `CHANGELOG.md`, with no API calls and no limit.
- `atlas … | head` crashed with "failed printing to stdout: Broken pipe"; short commands now end quietly.
- The installer works when the GitHub API is rate-limited.

## [1.1.0] — 2026-10-12

Atlas 1.1 is the first open-source release: the code is public under MIT OR Apache-2.0, with a public repository, CI on pull requests and a docs site at https://atlas.codeatlas.com.br/docs. Atlas Desktop gets a new shell (a space per project, sidebars that peek in from the window edge, trackpad swipes), a project panel with live charts, viewers for images, PDF, media and Markdown, a Ghostty-style terminal keyboard, and updates you can read before you install them. `atlas.yaml`, the CLI, the TUI and the MCP tools stay compatible with 1.0.

### Highlights

- **Open source.** MIT OR Apache-2.0, a public repository, DCO sign-off, CI on every pull request, governance, a privacy statement and a docs site.
- **A new desktop shell.** Every project is a space with its own icon and color. Sidebars hide and peek in from the window edge, two-finger swipes switch spaces and tabs, and the header shows a breadcrumb with back and forward history.
- **A project panel that shows the stack live.** KPIs, memory, CPU and error-rate charts, a health timeline, service cards with sparklines, an Actions menu, an Action output drawer, an Activity drawer and a Setup strip.
- **Look at more things without leaving the app.** Images, PDF, video and audio, Markdown and a hex fallback open in viewers; project-wide search runs on ⌘⇧F.
- **Terminal keys that match Ghostty.** ⌘⌫, ⌥⌫, ⌘←/→, ⌘K clear, font zoom, click to move the cursor, copy on select and Option as Alt. The terminal host can now be upgraded without closing your terminals.
- **Logs by time.** A time range in the TUI (`V`) and the desktop, burst-safe streaming with gap markers, and one level-detection rule shared by both.
- **Updates, shown properly.** An Update pill, a What's new sheet with the release notes of every version you skipped, and an unobtrusive amber line on dev builds.
- **Native macOS behavior.** Real menus, ⌘S to save, ⌘⇧T to reopen a closed tab, ⌃Tab by recent use, a menu-bar popover and a new app icon.

### Workspace and navigation

- **Spaces.** Every project is a space with its own worktrees, tabs, panes and docks, and a color that tints the selection, the header and focus states. Switch with ⌥⌘← / ⌥⌘→ or ⌃1…⌃9.
- **Project icons.** Each project gets an icon: your emoji or Lucide icon, the repo's own logo or favicon (auto-detected), or a monogram, plus an optional color. Right-click a project → **Change icon and color…**. Shown in the sidebar, the header breadcrumb, the panel, the palettes, the Files header and the tray.
- **Sidebar.** Shows the active project and its worktrees (a single checkout is just its own row); other projects are collapsed under **Other projects**; the bottom strip is now project icons, not dots.
- **Magic sidebars.** ⌃⌘S hides the left sidebar and ⌘R the right one. Move the pointer to the window edge and the sidebar slides in over the content (after ~60 ms, or at once on a flick), stays while the pointer is on it, slides out 250 ms after you leave, and ⎋ closes it. A menu or dialog opened from it keeps it open. The peeked panel is opaque.
- **Trackpad gestures.** Two-finger swipes over the sidebar switch space, over the tab strip switch tab, and over content where nothing can scroll go back or forward (⌘[ / ⌘]). A swipe only starts when nothing under the pointer can scroll that way, one swipe is one switch, and with _Reduce motion_ on the switch is instant. Pinch is never a swipe.
- **Breadcrumb and history.** The header shows `Space › worktree › tab`, each part clickable. ⌘[ / ⌘] walk the worktrees and tabs you visited, skipping ones that no longer exist.
- **Compact header.** One row with the health pill, the notifications bell, dock toggles, **Activity**, **Actions ▾**, the `…` menu and **Start / Stop**.
- **Pinned Panel tab.** The Panel is always the first tab of the first pane, a compact icon without a close button. ⌘W on it only says so; it cannot be dragged, split or moved; it is recreated if a worktree opens without one.
- **Docks.** Left, bottom and right docks have header toggles that show their state and shortcut. Drag an edge to resize (arrow keys nudge, double-click resets); sizes are remembered.

### Project panel

- **KPI row:** services running of total, restarts in the last hour, error lines in the last 5 minutes, and memory and CPU of the whole stack. Tiles turn amber or red when something needs a look.
- **Service cards,** failed and starting first: state ring, port (click to open or copy the URL), CPU and memory sparklines of the last ~2 minutes, last log line, restart badge, `depends_on` chips, and on hover **Restart**, **Stop / Start**, **Logs** and **Terminal** (opened in the service's `dir`). A failed card shows its reason and **View logs**. Arrows, Home, End and ↩ navigate; **R** restarts a running service after a confirmation.
- **Live charts:** stacked-area memory and CPU for the heaviest services, an error-rate bar chart over the last 5 minutes, and a **Health over time** timeline of running, starting and failed bands for the last 10 minutes; click a lane to open its logs. Samples are taken in the app every 3 s and kept for 10 minutes.
- **Actions menu** (header **⚡ Actions ▾**): every `actions:` entry of `atlas.yaml`, grouped like the TUI help, with its bare key. Destructive ones (`confirm:`) are marked and ask first; disabled ones say why. A running action shows a spinner and its label, and finishes with a result chip (or a toast for a project you are not looking at).
- **Action output drawer.** Keeps the output of the last 10 action runs per project (up to 5000 lines each), newest first with status, start time and duration. ANSI colors, follows the end while it runs, **Copy** and **Run again**; `path:line[:col]` opens in the editor, URLs in the preview browser. Opening the app mid-run replays the last 500 lines the runner kept per recent run. Open it from the Actions button, the result chip, or ⌘⇧P → _Show action output_.
- **Activity drawer.** The stack's events grouped by time. Bursts collapse into one row (`server restarted 3×`) and identical consecutive alerts fold (`boom ×4`); filter by **All / Errors / Restarts / Actions**; click a row to open that service's logs at that moment (a time range that would hide it is cleared, with a toast). The header button shows an unread count.
- **Setup strip.** Shown when the project has a dependency step (`pre_command` or an auto-detected installer): last run, result, **Run again** and **View output**. While it runs it tails live output; on failure it turns red with the reason, **Retry** and the last lines.
- **Empty states:** with the stack stopped, a card says what **Start** will launch; a project without services links to `atlas.yaml`.

### Files and search

- **Viewers by extension.** Images (png, jpg, gif, webp, avif, bmp, ico, svg) on a checkerboard: fit to view, ⌘+ / ⌘− / ⌘0, pinch or ⌘-wheel zoom, drag to pan, double-click toggles 100%, pixel-crisp past 200%, an info bar and copy image; SVG has an _Edit source_ toggle. **PDF** renders with pdf.js (page thumbnails, zoom, find). **Video and audio** (mp4, mov, webm, mp3, wav, ogg, m4a) use native players. **Markdown** previews on ⌘⇧M (syntax-colored code, tables, task lists, images relative to the file). Anything else shows its size, **Open externally**, **Reveal in Finder** and a hex dump of the first 4 KB. Media loads in 8 MB chunks up to 200 MB; text opens up to 2 MB.
- **Search in project (⌘⇧F).** Searches every file in the worktree as you type (a newer query cancels the older one), with match case, whole word and regex toggles and include/exclude globs. Results are grouped by file; ↑ ↓ move, ← → fold, ↩ opens the file at the line and column. Runs `rg` through the terminal host (so it also works on SSH hosts, honoring `.gitignore`) and falls back to `git grep`. Shows at most 2000 matches in 200 files and says when results were cut.
- **Explorer keyboard.** Arrows, ←/→, Home, End and ↩ navigate; F2 or _Rename_ and _New file_ edit in place; the locate button reveals the active file. The Explorer is git-colored and live.

### GPU terminal

- **Ghostty-style keys** (with a GPU terminal focused): ⌘⌫ deletes to line start, ⌥⌫ deletes a word back, ⌘←/⌘→ go to line start/end, ⌥←/⌥→ move by word, ⌥Delete deletes a word forward. With the Kitty keyboard protocol on, programs get the real key and modifiers instead.
- **Terminal actions:** ⌘K clears the screen and scrollback; ⌘A selects all; ⌘↑/⌘↓ jump between prompts; ⌘Home/⌘End and ⌘PgUp/⌘PgDn scroll; ⌘D / ⌘⇧D split right / down. See [docs/terminal.md](docs/terminal.md#keyboard).
- **Font zoom:** ⌘+ / ⌘= / ⌘− / ⌘0 change the font size of that terminal only, live (6–48 pt).
- **Click to move:** a plain click on the prompt being edited moves the shell cursor there (needs OSC 133; `terminal.click_to_move`, on by default). **Copy on select** (`terminal.copy_on_select`, on). **Option as Alt** (`terminal.option_as_alt`: `both`, `left`, `right`, `none`; default `both`).
- **Alternate-screen wheel:** `less`, `vim` and `htop` get Up/Down arrows from the wheel (xterm alternate scroll, DECSET 1007).
- **Search and links:** ⌘F regex search with a match counter and highlights; hold ⌘ over a URL or OSC 8 link to underline it, ⌘-click opens it (Atlas browser, else system browser).
- **Live preferences:** theme, font size, cursor, scrollback, ligatures, minimum contrast and the OSC 52 policy apply to terminals that are already open.
- **Live terminal-host upgrade.** After an update, the new `atlas hostd --takeover` receives every pty master (`SCM_RIGHTS`), the session state and the pid-file lock, and the old process exits. Programs keep running, scrollback keeps appending to the same files, the app reattaches and shows a _Terminal host updated_ toast. If the successor fails before confirming, the old daemon takes its ptys back. `atlas hostd --upgrade` does the same from a shell. A protocol 1 host (the one in 1.0) cannot hand over: it restarts silently when no terminal runs, otherwise terminals keep using xterm.js and Settings offers **Restart terminal host**; later upgrades are live. Pipe-mode sessions (`omp --mode rpc-ui`) end with the old daemon.

### Logs

- **Time ranges.** The TUI's `V` cycles `last 1m → 5m → 15m → 1h → since restart → since start`, then a custom prompt (`14:05` or `14:05–14:20`, today, both ends inclusive; `-`, `–`, `—` or `..` separate), then all time. The desktop has a clock chip in the Logs toolbar with the same presets and custom range. The range composes with the service, level, find and filter, and counts, error/warning totals and the "N new lines" pill follow it. `last N` windows slide: lines that age out are dropped without rescanning. The TUI shows a `time: …` badge; it is not saved between sessions.
- **Burst-safe streaming.** A client that falls behind skips log lines and shows an "N lines skipped" marker instead of being disconnected; the full output stays in `.logs/`. The TUI keeps its view in sync with the buffer by trimming exactly the rows that were evicted, so a chatty service no longer leaves stale rows on the All tab.
- **Consistent levels.** The TUI and the desktop use the same level rule, checked against one shared fixture (`testdata/log-levels.json`): `0 errors found`, `GET /api/error 500` and `TypeError: x` stay info, `ERROR:`, `panic:` and red ANSI are errors.
- **"Since restart" survives eviction:** the newest restart marker per service is remembered even after its line leaves the ring.

## [1.0.0] — 2026-10-11

Atlas 1.0 turns Atlas Desktop into a full development environment: a native GPU terminal, a Zed-style workspace around it, and a log viewer built for real traffic, in both the desktop app and the TUI. `atlas.yaml`, the CLI, the TUI and the MCP tools stay compatible with 0.6.

### Highlights

- **A GPU terminal built into Atlas Desktop.** Terminals are drawn natively with Metal (wgpu) instead of a web view: 120 Hz, under 1 ms of render work per frame, images, color emoji, ligatures and shell integration. On by default for local terminals.
- **A Zed-style workspace.** Left, right and bottom docks, pane zoom, a command palette with every action, go to file and go to symbol, rebindable shortcuts, Zed themes, file icons, and a settings page for fonts, terminal and panels.
- **Logs built for real traffic, in the TUI and the desktop.** Search like a terminal (match counter, next/previous, highlights), jump to the next error or warning, click a URL or `path:line` to open it, full color fidelity, and no freezes under bursts of hundreds of thousands of lines.

### GPU terminal

- **Rendering:** Metal through wgpu. Each terminal is a native view over its pane, with its own render thread that sleeps until there is output. Frames are vsync-paced at 120 Hz on ProMotion displays; render work is ~0.2–0.3 ms p95 for a 144×44 grid in an optimized build.
- **Text:** bundled JetBrains Mono with a Nerd Font symbols fallback, bold/italic, programming ligatures (`->`, `!=`, `=>`, `===`; toggle in settings), color emoji including ZWJ sequences, flags, skin tones and VS16, a minimum-contrast option (WCAG ratio), and pixel-exact box drawing, block elements, braille, sextants and powerline glyphs that tile without gaps.
- **Underline styles:** single, double, curly, dotted and dashed, in color (SGR 58), plus strikethrough.
- **Images:** the Kitty graphics protocol (PNG, RGB/RGBA, zlib, chunked transfers, files, placement ids, z-order above or below text, quiet mode) and sixel. Images scroll with the text and leave with the alternate screen.
- **Shell integration:** OSC 133 prompt marks (⌘↑ / ⌘↓ jump between prompts, exit codes), OSC 7 working directory (Restart reopens there), titles, bell (flash, Dock attention when unfocused).
- **Interaction:** native selection (character, word, line and ⌥ block), 10,000 lines of scrollback (configurable) with a scrollbar, ⌘F regex search with match counter and highlights, clickable URLs and OSC 8 links (⌘-click), copy and bracketed paste, dropping a file pastes its path.
- **Keyboard and modes:** the Kitty keyboard protocol, synchronized output (mode 2026), grapheme clusters (mode 2027), cursor shapes and blinking (hollow when unfocused).
- **Clipboard safety:** a program writing the clipboard with OSC 52 now asks first (`terminal.osc52`: ask, allow or deny). Reading the clipboard is always denied.
- **Live settings:** theme, font size, cursor, scrollback, ligatures and contrast apply to open terminals.
- **Backpressure:** the terminal host now slows a program down when the screen cannot keep up, like a native terminal, instead of buffering its output in memory. A client that stops reading for 2 s is dropped so it cannot freeze the program.
- Terminals of SSH-host worktrees keep using the classic (xterm.js) renderer, as does a terminal host started by an older Atlas until it restarts (Settings → Editor & terminal → Restart terminal host).

Benchmarks against Ghostty on the same machine are in [docs/terminal.md](docs/terminal.md#performance).

### Workspace

- **Docks:** ⌘B left (project or git panel), ⌘R right, ⌘J bottom (its own terminal tabs), ⌥⌘Y all docks, ⇧Esc zooms the focused pane, plus a centered layout. Docks are resizable by dragging and remember their size; header buttons show their state.
- **Palettes:** ⌘⇧P command palette (every command with its current shortcut, recently used first, matched characters highlighted), ⌘K jump to worktrees and terminals, ⌘P go to file with file icons, ⌘⇧O go to symbol in the open editor.
- **Shortcuts:** every shortcut is a named command with Zed's names and defaults. Rebind or unbind them in Settings → Keyboard shortcuts, or under `keymap` in `~/.atlas/desktop/settings.json`.
- **Themes:** Zed theme files (v0.2.0 format) color the whole app, the code editor and the terminals. Bundled: Atlas Dark/Light and One Dark/Light; add your own in `~/.atlas/desktop/themes/`. Separate light and dark choices follow the system appearance.
- **File icons:** the Material Icon Theme in the explorer, tabs and go to file.
- **Settings → Editor & terminal:** editor and interface fonts, terminal font size, cursor, scrollback, OSC 52 policy, ligatures and contrast, explorer side, icons and indentation, active-pane border and inactive-pane dimming (Zed setting names).
- **Polish:** welcome screens for a first run and for an empty worktree, loading skeletons, in-app confirmation dialogs instead of browser prompts, tooltips that show the current shortcut, tidier sidebar, explorer, agents and dashboard views.

### Logs

- **Robust ingestion (runner):** real lines are assembled from the raw pipe. Partial lines (prompts) show after 150 ms of silence, `\r\n` is one line break, a lone `\r` keeps only a progress bar's last state, invalid UTF-8 is replaced, and lines over 16 KiB are cut with `… [truncated]`. Level, timestamp and sequence number are computed once per line.
- **Restart separators:** a dim `──── HH:MM:SS restarted ────` rule separates a service's runs.
- **Bursts never cut the desktop off:** a client that falls behind skips log lines and gets a "N lines skipped" marker (the full output stays in `.logs/`), instead of being disconnected. Output reaches the app in ~16 ms batches.
- **TUI:** `/` find with `n/N` counter and highlights across the whole buffer, `]e`/`[e` and `]w`/`[w` jump between errors and warnings, `}`/`{` move between URLs and `path:line[:col]` links and `o` opens them (browser or your GUI editor at the line; copied otherwise), `y` copies a link. Rendering is O(visible rows) with a cached wrap index.
- **Desktop:** ⌘F find with regex/case toggles, `n/N` counter, Enter/⇧Enter and highlights; filter mode hides non-matching lines; `e`/`w` jump to the next error/warning; ⌘-click opens URLs in the Atlas browser and `path:line` in an editor tab at that line; error counts on service chips; timestamps and wrap toggles; a "N new lines" pill while scrolled up; Copy for AI of the filtered view. The view keeps 50k lines, filters incrementally (a filter change re-scans in idle slices) and parses ANSI only for visible rows. Colors follow the theme's terminal palette, including 256 colors, truecolor, underline styles and OSC 8 links.
- **MCP:** `atlas_logs_search` uses the same matcher as the TUI and stays case-insensitive.
