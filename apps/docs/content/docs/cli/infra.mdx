## atlas infra setup

Provision a fresh server with your chosen container runtime.

### Usage

```bash
atlas infra setup [options]
```

### Description

Connects to a server via SSH and installs the full production stack: container runtime, ingress proxy, TLS, and monitoring.

### Options

| Flag | Description |
|------|-------------|
| `--host` | SSH host (e.g., `root@1.2.3.4` or SSH config alias) |
| `--domain` | Base domain (e.g., `myapp.com`) |
| `--runtime` | Container runtime: `k3s`, `swarm`, or `firecracker` |
| `--skip-monitoring` | Skip Prometheus, Grafana, and Loki installation |
| `--skip-argocd` | Skip ArgoCD installation (K3s only) |
| `--tunnel` | Enable Cloudflare Tunnel |
| `--cf-token` | Cloudflare API token (required with `--tunnel`) |
| `--cf-account` | Cloudflare account ID (required with `--tunnel`) |
| `--yes, -y` | Non-interactive mode |

### What gets installed

| Component | K3s | Swarm | Firecracker |
|-----------|-----|-------|-------------|
| Runtime | K3s binary | Docker + Swarm | Firecracker + atlas-vmm |
| Ingress | Traefik v3 (Helm) | Traefik v3 (Docker) | Traefik v3 (binary) |
| TLS | cert-manager | Traefik ACME | Traefik ACME |
| Monitoring | Prometheus + Grafana + Loki (Helm) | Prometheus + Grafana + Loki (Docker) | node-exporter |
| GitOps | ArgoCD | N/A | N/A |

### Examples

```bash
# Interactive
atlas infra setup --host root@my-server

# Non-interactive
atlas infra setup \
  --host root@1.2.3.4 \
  --domain myapp.com \
  --runtime k3s \
  --yes

# With Cloudflare Tunnel
atlas infra setup \
  --host root@vps \
  --domain myapp.com \
  --runtime swarm \
  --tunnel \
  --cf-token $CF_TOKEN \
  --cf-account $CF_ACCOUNT \
  --yes
```

## atlas infra migrate

Switch between container runtimes on an existing server.

### Usage

```bash
atlas infra migrate [options]
```

### Options

| Flag | Description |
|------|-------------|
| `--to` | Target runtime: `k3s`, `swarm`, or `firecracker` |
| `--host` | SSH host (defaults to config) |
| `--yes, -y` | Non-interactive mode |

### Description

Displays a migration plan showing what you gain and lose, lists running services that need re-deployment, and warns about potential data loss from non-migrated volumes.

After migration, re-deploy your services:

```bash
atlas deploy
```

<Callout type="warn">
  Persistent volumes are not migrated automatically. Back up your data before switching runtimes.
</Callout>
