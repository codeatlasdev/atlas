---
title: DNS & HTTPS
description: Automatic DNS records via Cloudflare and TLS certificates via Let's Encrypt.
---

Atlas manages DNS and HTTPS automatically. You set a `domain` field in `atlas.yaml`, and Atlas configures everything on deploy.

## DNS via Cloudflare

Atlas uses the Cloudflare API to manage DNS records. When you deploy a service with a `domain` field:

1. Atlas resolves the Cloudflare zone for your root domain
2. Creates or updates an A record pointing to your server IP
3. Enables Cloudflare proxy by default (CDN, DDoS protection)

The operation is idempotent. Running `atlas deploy` multiple times does not create duplicate records. If the record already points to the correct IP, Atlas skips the update.

## Cloudflare Tunnels

For servers without a public IP (or when you want to avoid exposing ports 80/443), Atlas supports Cloudflare Tunnels:

```bash
atlas infra setup --host root@vps --tunnel --cf-token $TOKEN --cf-account $ACCOUNT
```

The tunnel implementation varies by runtime:

| Runtime | Tunnel method |
|---------|--------------|
| K3s | `cloudflare-tunnel-ingress-controller` Helm chart |
| Swarm | Not yet supported |
| Firecracker | Traefik file provider with tunnel CNAME |

Traffic routes through Cloudflare's network instead of hitting your server directly.

## HTTPS

TLS certificates are provisioned automatically after DNS is configured:

| Runtime | Provider | Mechanism |
|---------|----------|-----------|
| K3s | cert-manager | ClusterIssuer with Let's Encrypt HTTP-01 challenge |
| Swarm | Traefik | Built-in ACME resolver with HTTP challenge |
| Firecracker | Traefik | Built-in ACME resolver (systemd service) |

All runtimes:
- Issue certificates from Let's Encrypt
- Auto-renew before expiration
- Redirect HTTP to HTTPS

No manual certificate management is required.

## Requirements

- A domain with DNS managed by Cloudflare (free plan is sufficient)
- A Cloudflare API token with Zone:DNS:Edit permission (set via `atlas login` or `atlas panel config`)
- Server reachable on ports 80 and 443 (unless using Tunnels)
