The Control Panel is the central API. Every action flows through it: deploys, DNS configuration, secret management, log streaming, and server provisioning.

## Tech stack

| Component | Technology |
|-----------|-----------|
| Runtime | Bun |
| Framework | Elysia |
| RPC | oRPC (type-safe, shared contract with CLI) |
| Database | PostgreSQL 17 + Drizzle ORM |
| Auth | JWT (HMAC-SHA256) + GitHub OAuth |
| Encryption | AES-256-GCM via Web Crypto API |

## API transport

The Panel uses oRPC mounted at `/rpc/*` for all CRUD operations. Custom Elysia routes handle OAuth and SSE streaming:

| Path | Method | Purpose |
|------|--------|---------|
| `/rpc/*` | ALL | oRPC procedures (type-safe RPC) |
| `/auth/github` | GET | Initiate GitHub OAuth |
| `/auth/github/callback` | GET | OAuth callback |
| `/auth/token` | POST | Exchange code for token (programmatic) |
| `/logs/project/:id` | GET | SSE log streaming |
| `/health` | GET | Health check |

## Multi-tenant architecture

All data is scoped by organization. Users belong to an org, servers belong to an org, projects belong to an org. The `orgId` is extracted from the JWT on every request.

## Roles

| Role | Permissions |
|------|------------|
| admin | Full access: settings, servers, deploys, secrets, users |
| dev | Deploy, manage secrets, stream logs, preview environments |
| viewer | Read-only access to projects and deploy history |

The first user to authenticate in an organization is automatically assigned the admin role.
