# Platform rules (atlas-core: `sys`, `ipc`, paths)

Nested notes, loaded when you work under `crates/atlas-core/`. Moved verbatim from the old root `AGENTS.md`; the rule that matters everywhere (shared code never calls `libc`/`nix`; every GUI/hostd child needs `no_window()`) stays in the root.

- Linux: the whole workspace builds (Atlas Desktop on WebKitGTK; the native GPU terminal and capture are macOS only, stubbed in `term_stub.rs`, and terminals use xterm.js; agent instances work on Linux, see "Debugging Atlas Desktop"). Packaging: `tauri.linux.conf.json` (AppImage, .deb, .rpm, each with the CLI) and `packaging/arch/` (pacman package from the .deb).
- Windows (x64): the whole workspace builds and tests (CI job `rust-windows`). Platform code goes through `atlas_core::sys` (pids, kills, process tree, `try_lock`, `shell`/`shell_argv`, `no_window`, `spawn_detached`) and `atlas_core::ipc` (Unix sockets, or named pipes derived from the same path), never `libc`/`nix` directly in shared code. hostd runs terminals on ConPTY, has no live `upgrade` (no `upgrade` cap; a restart instead), and answers ConPTY's startup cursor query itself. Every child of the GUI app or hostd needs `no_window()` (or `spawn_detached`), else a console window flashes. `atlas.yaml` commands run via `cmd /d /s /c`; tests that spawn shell one-liners go through `runtime::process::test_sh`. Paths are stored with forward slashes (`atlas_core::paths::canonical`). Packaging: `tauri.windows.conf.json` (per-user NSIS installer), cross-built on Linux with cargo-xwin in `release.yml` (`build-windows`).
