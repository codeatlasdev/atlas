# Audit: Host Authority / Security Plane, Durable Execution Plane, Agent Runtime

Baseline of `main` at `72b47fc3` (the main checkout, clean tree, macOS arm64). Read-only audit; nothing in any repo was modified. Test logs are in `/tmp/auditrt/*.log` (local to the audit run, not kept).

## 1. Scope

RFC layers: Host Authority/Security Plane (isolation, policy enforcement, secrets, approvals, resource limits, audit, egress, revocation), Durable Execution Plane (runs, checkpoints, events, recovery, idempotency), Agent Runtime (identity, lifecycle). RFC §5, §11, §15, §21.3, §30, §31; acceptance scenarios D (human approval) and E (failure recovery).

Code read: `crates/atlas-host/src/crew/{approval.rs, hub.rs, mod.rs, memory_cap.rs, runner/**, engine/{launch,omp}.rs, spawn/{cgroup,provision,validate}.rs, store/{mod,tasklog,usage}.rs, audit/**, capture/**}`, `agents/{hook_server,hook_auth,mod}.rs`, `crates/atlas-cli/src/commands/crew/{update,binary,isolation,install}.rs`, `docs/crew.md` (security, audit, restart, approvals).

Not covered here (other auditors): organization model, comms/delegation, memory, UX, MCP tools surface.

Classification key: IV = Implemented and verified; II = Implemented, incomplete; P = Prototype; PL = Planned; M = Missing; U = Unknown.

## 3. Existing primitives worth reusing

Data models and files
- `Task` + `tasks.jsonl` append-only log with fold-by-id, step deltas and a saved index `tasks.idx` (`crew/store/tasklog.rs`, `store/mod.rs:359`). Extend with optional fields (all `#[serde(default)]`); old hostds ignore unknown fields (see section 5).
- `Task.restarts`/`resumed` and `recover()` (`runner/recover.rs`): the resume cap and "task that takes the daemon down cannot loop" logic is a ready-made durable-run recovery policy.
- `TaskAction` enum (`store/mod.rs:300-338`) and `waiting_action` parking (`runner/action.rs`): persistent human-in-the-loop cards that survive restart; the natural carrier for org-level approval requests.
- `UsageRecord`, `usage.jsonl` rotation + `crewmate_usage` API (`store/usage.rs`, `handlers/tasks.rs:312`): accounting source for budgets.
- `audit.jsonl` + `Audit::record` single writer, `redact::scrub`, rotation (`crew/audit/`), `crewmate_audit`/`crew_audit` read APIs (`crew/mod.rs:197-205`). Add fields (`run_id`, `policy`, `result`) by merging into `fields`; readers are tolerant.
- `CrewSettings` in `crew.json` (`store/mod.rs:497-`): `paused`, `max_agents`, `agent_memory_max`, `default_approval`, `allow_bypass`; `load_crew_settings` fails closed (paused) on corrupt file.
- `Crewmate.triggers`, `Trigger`, `after-crewmate` `chain` (`Task.chain`): loop prevention for chained work.

- Events: `agent_approval`, `agent_approval_done`, `crew_paused`, `crewmate_updated`, `approval_unanswered` (`agents/mod.rs:432-497`, `crew/events.rs`).

Runtime behaviour

## 4. Gaps and smallest evolution

1. Durable run record with explicit states. No `WaitingApproval`, `Recovering`, `OutcomeUncertain`, `Paused` (pause = `Cancelled`). Smallest: add `TaskState` variants as additive enum values only after every client tolerates unknown states (mobile/desktop clients decode `TaskState`; see section 5), or keep `TaskState` and add an optional `run: { phase, waiting_on, recovery }` object on `Task` that is derived/written by the runner. Pending approvals would be written as `waiting_on: {kind: "approval", req}`.
2. Tool-call journal with idempotency and uncertain-outcome. Today `tool_call` audit lines record intent only (no result) and `tape` keeps outputs in memory, dropped at task end (`runner/tape.rs`). Smallest: persist per-task `tool_calls.jsonl` (call id, tool, canonical input hash, start/end, result digest, `class: read|write|external`, `outcome: confirmed|unknown`) from the same `tool_execution_end`/`post_tool_use` feed the tape already receives; on recovery mark `started && !ended` external calls `uncertain` and put them in the resume prompt, and require a human card for non-idempotent ones. No new engine is needed.
3. Approval record and binding. Persist a request `{id, task, crewmate, tool, canonical_hash(tool,input), policy_ref, created_at, expires_at}` and make `agent_approve` carry the hash; refuse when the held call's hash differs. Today the binding is only `(pane, req)` and grants are `tool:command`/`edit`. Add TTL to task grants (`State.grants`, `approval.rs:489`).
4. Policy layers and capabilities. `classify` is the single hook: add `Policy::evaluate(org, dept, crewmate, task, action) -> Allow|Hold|Deny` ahead of the mode check, loaded from files hostd owns (agent cannot write them; `crew-runtime` is read-only to the crewmate). Keep `Mode` as the lowest-priority fallback so existing crews do not change.
5. Budgets. `read_usage` already sums by crewmate/time; add a `budgets` section to `crew.json` (per crewmate/day/task, cost and tokens) checked in `slots::take` (before start) and after each turn in `conversation.rs:260-270` (stop or park with a card). Gaps to close first: codex and omp report no `cost_usd` (`engine/codex.rs:129`, `engine/omp.rs:254`) and terminal agents report no usage, so enforceable budgets today are for claude/opencode turns only; token-based or wall-time budgets cover the rest. Delegation budget needs run lineage (gap 1).
6. Audit completeness and integrity. Add `run_id`, `actor` (person, not device class), `policy`, `result`, `correlation` fields; add `fsync` for decision records (`append_line(..., durable=true)` exists, `jsonl.rs:60`), optional hash chaining `prev_hash` per line, and an archive (gzip like `usage::rotate`) instead of deleting the 5th file. Record tool results (hash) from the tape feed.
7. Browser sandbox (N4). Run `runner.mjs` through the spawn helper as the crewmate (an `Exec::isolated` already exists in `engine/launch.rs`) with an nft exception for the guard proxy port, or enable Chromium's sandbox under a dedicated user; add a concurrency limit and put it in the crewmate cgroup.
8. Egress policy per crewmate. `egress_ruleset` already takes `(user, Policy)`; only `System::egress` hardcodes `Policy::default()` (`provision.rs:409-415`). Read per-crewmate policy from a root-owned file written by provisioning, and add a domain allowlist via an HTTP(S) proxy for the capability plane if "domain" is required (nft is IP only).
9. Revocation. Add per-crewmate disable (stop + refuse tasks), per-secret delete, per-grant revoke. `crewmate` has no `disabled` field (only `Trigger.enabled`). Reuse `set_paused` structure.
10. Secrets. Move from env delivery to broker/lease for sensitive ones (the GitHub App helper `credential_reply` is the model: token minted per git operation, `hook_server.rs:355-358`). Add `set_secret` caller authorization beyond "any owner client" and an audit of reads (`secret_env` is called per turn without an audit line).
11. Non-askable engines. codex/opencode run unattended in bypass; for autonomous use either restrict autonomy-bearing crewmates to `claude`/`omp` or add a hostd shell wrapper; today `unsupported_engine` only refuses non-bypass modes (`approval.rs:921`).
12. Resource limits: CPU/IO and per-run wall time; the 2 h timeout is global.

## 5. Compatibility constraints and migration risks

- `tasks.jsonl`: append-only, last full record wins, step-delta lines `{"step_of":...}`; a newer file read by an older hostd "just misses the in-flight steps" (`tasklog.rs` header). All `Task` fields use `#[serde(default)]`; adding optional fields is safe in both directions. Adding a `TaskState` enum variant is NOT safe: older hostd/clients fail to parse the record (an unknown line is parked in `unknown` and preserved by compaction, `tasklog.rs`, but the task disappears from that hostd's view [INFERENCE from the `unknown` handling]); mobile (`apps/mobile`) and desktop decode `state` as a closed set [not verified in the clients; Unknown, belongs to AuditSurfacesAX].
- `tasks.idx` has `IDX_VERSION=1`; another version is ignored and rebuilt, so format changes are cheap.
- `crew.json` is the kill switch store: unparseable => paused. A new field is safe (`#[serde(default)]`), but a rolled-back hostd that rewrites `crew.json` through its own `CrewSettings` drops unknown fields (serde ignores and rewrites) [INFERENCE: `save_crew_settings` serializes its own struct, `store/mod.rs:1123`], silently losing budgets/policies. Keep new policy in separate files (not inside `crew.json`) or add `#[serde(flatten)] extra`.
- Legacy names: `bots/`, `bot.json`, `approval: ask|auto` alias (`store/mod.rs:5-28,267`); `crewmate_list` still emits legacy `approval`. Keep.
- Wire protocol: `PROTO = 2` (`protocol.rs:77`); `protocol_golden.rs` fixes the wire shape and the mobile minimum (`kMinHostProto`). Scope table in `mobile/mod.rs:532-582`: each new command must be classified (a test fails otherwise, per memory note on `client.rs` QUICK/LONG/SPECIAL) and fixtures regenerated (`UPDATE_FIXTURES=1`).
- Spawn-helper protocol (`spawn/wire.rs`, `validate.rs`): a root service on the server; installed by `atlas crew install`, so a new hostd with a new helper request requires the operator to re-run install (the helper is separate from hostd). Old helper + new hostd: unknown request would be refused, so fail closed but tasks stop. `update` swaps only the binary and restarts `atlas-crew`; whether it also restarts helper sockets/units depends on re-running `install` [INFERENCE: `swap_script` restarts `SERVICE` only]. Cgroup/egress changes need `install` again.
- Egress and unit files live in `/etc/systemd/system` and `/etc/atlas-crew/egress.nft`; the Linux user slug is derived from the crewmate id, so id format changes would orphan users and directories.
- `audit.jsonl` readers skip unparseable lines and are tolerant of new fields; rotation is by file name `.1..4`. A change of the line shape needs a version field because `seq` continuity is read from the files on restart (`audit/mod.rs` `last_seq`).
- Old crew servers: a server older than the pause feature "reads as running" (docs/crew.md); mobile checks capabilities. Any new `crewmate_list` field must be optional for clients.
- Windows/macOS hosts: isolation, cgroups, nft are Linux only; hostd runs crewmates as the crew user elsewhere (docs/crew.md). Autonomous organizations on a Mac host lose all isolation [INFERENCE: `layout::active()` false off Linux].

## 6. Dependencies between capabilities

1. Tool-call journal (gap 2) before uncertain-outcome handling, idempotency keys, and truthful recovery (Scenario E).
2. Run record/state fields (gap 1) before: approval persistence, budgets per run/delegation, audit correlation by `run_id`, run lineage.
3. Approval record with canonical hash (gap 3) before policy-bound approvals and "material changes invalidate" (Scenario D); needs a stable canonical form of tool input (already normalized by `paths_of`/`commands_of` helpers).
4. Policy engine in `classify` (gap 4) before autonomy profiles, department/org policy, delegation constraints; revocation (gap 9) depends on it.
5. Usage accounting for every engine (codex/omp cost, terminal agents) before budgets are meaningful (gap 5).
6. Audit enrichment (gap 6) is independent but should land with 1-3 so new decisions record `run_id`/`policy`.
7. Browser sandbox (gap 7) and per-crewmate egress (gap 8) before enabling autonomous browsing/triggers for ../ac, ../zelvo, ../wi on a shared server; isolation only exists with the helper installed, so install must precede.
8. Non-askable engine restriction (gap 11) before granting any crewmate autonomy on a repo.

## 7. Open questions

- Should a paused crew keep held approvals open? `decide` does not read `paused` (not verified by test); is "pause = cancel" acceptable for long autonomous runs, or is a suspend state wanted?
- Which actions are "external/non-idempotent" for a software-evolution crew: `git push`, `gh pr create/merge`, `gh api`, deploy commands? A classifier like `destructive()` could be extended; who owns the list (platform vs project)?
- Is per-crewmate secret delivery by env acceptable for autonomous mode, given an injected agent can exfiltrate any env secret over 443 (egress allows all hosts on 22/80/443)?
- Do the four target projects (atlas, ac, zelvo, wi) run on a Linux crew server with the helper, or on the Mac host (no isolation, no cgroup, no nft)? This changes the baseline for isolation capabilities.
- Does the owner want per-engine budgets in USD (only claude/opencode report cost) or in tokens/time?
- The user-facing mobile/desktop closed-set decoding of `TaskState` and of crewmate `state` strings was not audited here (AuditSurfacesAX scope): confirm before adding states.
- Terminal-agent hooks: `atlas hook` "never fails (any problem = no output)" (`cli/.../hook/mod.rs:4`), meaning the agent's own prompt takes over when hostd is unreachable. Verify in a live run that the terminal claude stays in its own ask mode in that case (not run here).
