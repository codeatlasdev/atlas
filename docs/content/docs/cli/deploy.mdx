## Usage

```bash
atlas deploy [options]
```

## Description

Builds Docker images for each service defined in `atlas.yaml`, pushes them to GitHub Container Registry, and deploys to your cluster. Configures DNS and provisions TLS certificates for services with a `domain` field.

## Options

| Flag | Description |
|------|-------------|
| `--tag` | Image tag (default: git short SHA) |
| `--service, -s` | Deploy only a specific service |
| `--host` | Direct SSH deploy, bypasses the Panel |
| `--dry-run` | Simulate the deploy TUI without executing |
| `--yes, -y` | Non-interactive CI mode |

## Deploy modes

| Mode | When | Flow |
|------|------|------|
| Panel | `panelUrl` + `panelToken` configured | CLI → oRPC `deploys.trigger` → Panel SSHs into server |
| Direct | `--host` flag or only `host` in config | CLI → SSH into server directly |

## Cross-platform builds

Atlas detects the server architecture during `atlas infra setup` and stores it in config. If your local machine architecture differs from the server, Atlas uses `docker buildx build --platform {target} --push` for cross-compilation.

Override in `atlas.yaml`:

```yaml
platform: linux/amd64
```

## Examples

```bash
atlas deploy                        # Deploy all services
atlas deploy --service api          # Deploy only the API
atlas deploy --tag v2.0.0           # Custom image tag
atlas deploy --host root@server     # Direct SSH deploy
atlas deploy --dry-run              # Simulate TUI
atlas deploy --yes                  # CI mode
```

## Interactive vs CI output

In interactive mode (default), Atlas renders a TUI with real-time step progress. In CI mode (`--yes`), output uses plain text with `→`, `✓`, and `✗` prefixes.
