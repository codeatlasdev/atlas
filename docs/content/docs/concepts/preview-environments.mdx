---
title: Preview Environments
description: Ephemeral environments per branch with isolated networking.
---

Preview environments create an isolated deployment from your current branch with its own URL.

```bash
atlas preview start
```

## How it works

Atlas builds your images, pushes them, and deploys to an isolated environment with dedicated routing and TLS:

| Runtime | Isolation method |
|---------|-----------------|
| K3s | Separate Kubernetes namespace (`preview-{name}`) |
| Swarm | Separate Docker stack (`preview-{name}`) |
| Firecracker | Separate set of microVMs |

Each preview gets its own Traefik routing rules and TLS certificate.

## DNS

Preview URLs follow the pattern `{name}.preview.{domain}`.

Atlas creates a wildcard DNS record (`*.preview.{domain}`) pointing to your server. New previews do not require individual DNS entries.

## Commands

### Start

```bash
atlas preview start              # Uses current branch name
atlas preview start --name demo  # Custom name
```

### Stop

```bash
atlas preview stop --name feature-x
```

Tears down the namespace or stack and removes associated resources.

### List

```bash
atlas preview list
```

Output:

```
Active Previews

  feature-x    2h ago  https://feature-x.preview.myapp.com
  fix-auth     30m ago https://fix-auth.preview.myapp.com
```

## Cleanup

Previews run until you stop them. There is no automatic expiration.

<Callout type="info">
  Automatic expiration based on TTL is on the roadmap.
</Callout>
