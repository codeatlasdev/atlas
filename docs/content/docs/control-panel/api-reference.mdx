The Panel API uses oRPC for type-safe remote procedure calls. All procedures are mounted at `/rpc/*` and require JWT authentication via the `Authorization: Bearer {token}` header.

## Client setup

The CLI uses `@orpc/client` with `RPCLink`:

```typescript
import { createORPCClient } from "@orpc/client";
import { RPCLink } from "@orpc/client/fetch";

const link = new RPCLink({
  url: "https://panel.yourdomain.com/rpc",
  headers: () => ({
    Authorization: `Bearer ${token}`,
  }),
});

const client = createORPCClient(link);
```

## Procedures

### org

| Procedure | Input | Output | Role |
|-----------|-------|--------|------|
| `org.get` | none | Organization info (id, name, slug, configured flags) | any |
| `org.updateSettings` | cloudflareToken?, cloudflareAccountId?, githubToken?, githubAppId?, githubClientId?, githubClientSecret? | `{ ok: true }` | admin |

### servers

| Procedure | Input | Output | Role |
|-----------|-------|--------|------|
| `servers.list` | none | Array of servers (id, name, host, ip, runtime, status) | any |
| `servers.get` | `{ id }` | Server object | any |
| `servers.create` | `{ name, host, ip?, runtime?, provision?, domain? }` | Created server | admin |
| `servers.delete` | `{ id }` | `{ ok: true }` | admin |

### projects

| Procedure | Input | Output | Role |
|-----------|-------|--------|------|
| `projects.list` | none | Array of projects with server and domains | any |
| `projects.get` | `{ id }` | Project with server, domains, and last 10 deploys | any |
| `projects.create` | `{ name, serverId?, githubRepo?, domain?, atlasYaml? }` | Created project | admin |

### deploys

| Procedure | Input | Output | Role |
|-----------|-------|--------|------|
| `deploys.listByProject` | `{ projectId }` | Array of deploys (last 50) | any |
| `deploys.trigger` | `{ projectId, tag, services? }` | Created deploy (starts async pipeline) | admin, dev |
| `deploys.get` | `{ id }` | Deploy object with status | any |

### secrets

| Procedure | Input | Output | Role |
|-----------|-------|--------|------|
| `secrets.listKeys` | `{ projectId }` | Array of `{ key, updatedAt }` | any |
| `secrets.set` | `{ projectId, secrets: Record<string, string> }` | `{ ok, keys, synced }` | any |
| `secrets.delete` | `{ projectId, key }` | `{ ok, deleted, synced }` | any |
| `secrets.pullValues` | `{ projectId }` | `Record<string, string>` (decrypted) | any |

## Custom routes

These routes use standard HTTP outside of oRPC:

### Authentication

```
GET /auth/github?cli_port={port}
```

Initiates GitHub OAuth. The `cli_port` parameter tells the callback where to redirect the token.

```
GET /auth/github/callback?code={code}&state={state}
```

Exchanges the OAuth code for a JWT. If state starts with `cli:`, redirects the token to the CLI's local server at `http://localhost:{port}/callback?token=...`.

```
POST /auth/token
Content-Type: application/json

{ "code": "github_oauth_code" }
```

Programmatic token exchange. Returns `{ token, user }`.

### Log streaming

```
GET /logs/project/:projectId?service={name}&tail={n}&follow={bool}
Authorization: Bearer {token}
```

Returns a Server-Sent Events stream. Each event contains one log line:

```
data: 2024-01-15T10:30:00Z [api] Request received GET /health
```

### Health check

```
GET /health
```

Returns `{ "status": "ok", "version": "0.1.0" }`. No authentication required.
